# 检测签名与加固清单

> Detection Signatures & Hardening · 分类：AI 基础设施与供应链

## 1. 一句话定义

从防守方视角出发：用可落地的检测特征发现针对 AI 基础设施的侦察与利用，再用一份收敛清单把暴露面压到最小。

## 2. 机制与原理

- 对 AI 基础设施的攻击有明显的**流量形态**特征，因为这些组件是机器对机器调用的，缺少人类浏览行为。
- 侦察阶段的特征往往比利用阶段更容易捕获：端口扫描、路径枚举、结构列表请求都会留下密集而规律的记录。
- 加固的收益远大于检测：把管理面从公网收回，等于一次性消除一大类风险。
- 因此本页按"先收敛、再检测"的顺序组织。

## 3. 检测特征

| 场景 | 可观测特征 |
| --- | --- |
| 端口扫描 | 单一来源短时间内访问大量不同端口；命中集中在框架默认端口 |
| 服务识别 | 对同一端口的异常请求方法；响应状态分布高度一致（大量 404/401） |
| 路径枚举 | 对集合列表、实验列表、模型清单等固定路径的批量请求 |
| 结构枚举 | 连续调用组件的信息或配置接口 |
| 认证试探 | 同一账号或来源的失败登录密集出现 |
| 任务提交滥用 | 编排接口出现非常规镜像、异常资源请求 |
| 数据拉取异常 | 向量库或制品库的单次读取量远超正常业务 |

补充观察点：正常客户端会请求静态资源与页面，而扫描工具通常不会。缺少静态资源请求、却高频访问 API 的会话值得关注。

## 4. 加固清单

```text
一、暴露面收敛
  [ ] 管理端口（仪表盘、注册表、编排接口）不对外网开放
  [ ] 推理端口与管理端口分离，不共用对外入口
  [ ] 关闭不必要的管理与调试端点
  [ ] 定期清点暴露服务，找出台账之外实例

二、认证与授权
  [ ] 所有组件启用认证，禁用默认凭据
  [ ] 任务提交接口按角色授权，限制可用镜像与资源
  [ ] 向量库按租户划分命名空间并强制隔离
  [ ] 交互式环境（notebook）强制认证并限制挂载范围

三、信息收敛
  [ ] 关闭详细错误信息，不回显版本与内部路径
  [ ] 关闭或限制信息类端点（服务参数、配置查询）
  [ ] 最小化元数据字段，不写入与检索无关的业务标识

四、凭证管理
  [ ] 实验参数与配置中禁止明文凭证
  [ ] 凭证集中存放于专用密钥管理，按需短期下发
  [ ] 制品仓库启用签名校验，拒绝同名覆盖

五、监控与响应
  [ ] 对端口探测、路径枚举、结构枚举建立告警
  [ ] 记录组件的版本与变更，订阅厂商公告
  [ ] 按"是否对外可达"排列修复优先级
```


### 可直接落地的检测签名

| 侦察 / 利用行为 | 日志特征 | 对应动作 |
| --- | --- | --- |
| 模型枚举 | 单一 IP 在数秒内对 `/v2/models` 发起 10–50 次连续 GET——正常用户不会反复拉模型清单 | 限速 / 封禁 |
| 脚本化 MLflow 访问 | `/registered-models/list`、`/model-versions/search` 出现无 UI 会话 Cookie 的裸 API 调用（MLOKit 的典型形态） | 告警 |
| 外部拉取指标 | `/metrics` 请求来自监控网段之外——Prometheus 有固定 IP，其他任何来源都是在侦察 | 收紧 CIDR |
| AI 感知端口扫描 | 同一来源按 5000 → 8000 → 8001 → 8080 → 8265 → 8888 的顺序出现——不是随机扫描，是照着方法论在跑 | 边界阻断 |
| 路径遍历探测 | 制品端点出现 `../` 或 `%2e%2e%2f`——有人在探路径遍历类漏洞（对照 CVE 速查页） | 告警并升级 |
| Jupyter 无会话访问 | `/api/kernels`、`/api/contents` 请求不带有效会话 Cookie | 告警 |

### 快速收敛项（Quick Wins）

当天就能做、对暴露面收敛收益最大的几项：

```text
[ ] MLflow 启用认证：设置 MLFLOW_TRACKING_USERNAME / MLFLOW_TRACKING_PASSWORD，
    或放到带认证的反代后面；改掉一切默认口令（对照 CVE-2026-2635）
[ ] Jupyter 生产环境禁用 --allow-root 与 --ip=0.0.0.0，强制 token 认证；
    无 VPN / 入口级认证不得绑定 0.0.0.0
[ ] 边界封禁 AI 专用端口的外网可达：5000、8000-8002、8080、8265、8500/8501、8888、9000
[ ] Triton 生产环境以 --model-control-mode=none 关闭模型控制接口，
    防止未认证的模型加载 / 卸载
[ ] /metrics 限制在内部监控网段（Triton 8002、TorchServe 8082 泄露模型清单与 GPU 拓扑）
[ ] Hugging Face 令牌全部换成 fine-grained、只读、最小范围，并建立轮换机制
[ ] 从 ML 服务响应中剥离调试头与详细报错（版本号、内部路径、堆栈）
[ ] 审计 MinIO / S3 桶策略：模型权重不得放在公开可读的桶里
```

## 5. 检测与观察点

- 告警是否覆盖"侦察阶段"，而不是只覆盖利用阶段。
- 是否有组件不在资产台账内。
- 默认凭据是否已在部署阶段整改。
- 日志是否保留足够信息以支持事后回溯。

## 6. 防御与改进

- 先做暴露面收敛，再补检测规则：多数风险在收敛阶段就会消失。
- 把 AI 组件纳入统一的资产与漏洞管理流程，不另设一套。
- 定期复核"谁可以访问管理面"，把访问范围写进配置而非口头约定。
- 演练一次完整的侦察检测：从扫描开始，验证告警是否被触发。
