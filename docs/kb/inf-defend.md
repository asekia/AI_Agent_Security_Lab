# 检测签名与加固清单

> Detection Signatures & Hardening · 分类：AI 基础设施与供应链

## 1. 问题与威胁模型

**定义**：从防守方视角出发：用可落地的检测特征发现针对 AI 基础设施的侦察与利用，再用收敛清单把暴露面压到最小。

**威胁模型**：

| 角色 | 能力 |
| --- | --- |
| 攻击者 | 端口扫描、路径枚举、未认证访问、任务提交 |
| 目标 | 暴露在内网或公网的 AI 组件 |
| 前提 | 组件是机器对机器调用，缺少人类浏览行为 |

**命题**：侦察阶段的特征比利用阶段更容易捕获——端口扫描、路径枚举、结构列表请求都会留下密集规律的记录。

## 2. 原理推导

正常客户端与扫描工具的差异：

```text
正常：请求静态资源、带会话 Cookie、有页面跳转、频率低
扫描：只请求 API、无静态资源、状态码高度一致、频率高
```

因此检测特征围绕"机器节奏 + API-only + 状态分布"构建。

## 3. 攻击面与前提

| 场景 | 可观测特征 |
| --- | --- |
| 端口扫描 | 单一来源短时间访问大量端口，命中默认端口 |
| 服务识别 | 异常请求方法；响应状态高度一致（大量 404/401） |
| 路径枚举 | 对集合/实验/模型清单的批量请求 |
| 结构枚举 | 连续调用信息或配置接口 |
| 认证试探 | 同来源失败登录密集出现 |
| 任务提交滥用 | 非常规镜像、异常资源请求 |
| 数据拉取异常 | 向量库/制品库单次读取量远超业务 |

## 4. 实战步骤

### 步骤 1：建立基线

```text
记录正常访问模式：来源网段、请求路径分布、频率、User-Agent、状态码占比
```

### 步骤 2：部署检测签名

```text
SIG-01 模型枚举   ：单 IP 数秒内对 /v2/models 发起 10–50 次连续 GET
SIG-02 脚本化 API ：/registered-models/list、/model-versions/search
                    出现无 UI 会话 Cookie 的裸调用
SIG-03 指标外拉   ：/metrics 请求来自监控网段之外
SIG-04 端口序列   ：5000 → 8000 → 8001 → 8080 → 8265 → 8888 顺序扫描
SIG-05 遍历探测   ：制品端点出现 ../ 或 %2e%2e%2f
SIG-06 无会话访问 ：/api/kernels、/api/contents 不带有效会话 Cookie
```

### 步骤 3：执行快速收敛（Quick Wins）

```text
[ ] MLflow 启用认证（MLFLOW_TRACKING_USERNAME/PASSWORD 或认证反代），改默认口令
[ ] Jupyter 禁用 --allow-root 与 --ip=0.0.0.0，强制 token
[ ] 边界封禁 AI 专用端口：5000、8000-8002、8080、8265、8500/8501、8888、9000
[ ] Triton --model-control-mode=none 关闭模型控制接口
[ ] /metrics 限制在内部监控网段
[ ] HF 令牌改 fine-grained、只读、最小范围，建立轮换
[ ] 剥离调试头与详细报错
[ ] 审计 S3/MinIO 桶策略，模型权重不得公开可读
```

### 步骤 4：验证检测有效

```text
从外部发起一次模拟扫描，确认 SIG-01~06 至少触发 4 项；
对未触发项调整阈值或补日志字段。
```

## 5. 变体目录

| 编号 | 检测对象 | 特征 | 动作 |
| --- | --- | --- | --- |
| SIG-01 | 模型枚举 | 高频 /v2/models | 限速/封禁 |
| SIG-02 | 脚本化 MLflow | 裸 API 无 UI 会话 | 告警 |
| SIG-03 | 指标外拉 | 非监控网段 /metrics | 收紧 CIDR |
| SIG-04 | AI 端口扫描 | 固定端口序列 | 边界阻断 |
| SIG-05 | 遍历探测 | ../ 或 %2e%2e%2f | 告警升级 |
| SIG-06 | Jupyter 无会话 | 无 Cookie 的 /api | 告警 |

## 6. 检测与取证

- 告警是否覆盖"侦察阶段"而非只覆盖利用阶段。
- 是否有组件不在资产台账内。
- 默认凭据是否已在部署阶段整改。
- 日志是否保留足够信息支持回溯。
- 取证：源 IP、时间线、路径序列、响应码分布。

## 7. 防御与验证

1. **先收敛再检测**：多数风险在收敛阶段消失。
2. 把 AI 组件纳入统一资产与漏洞管理流程。
3. 定期复核"谁可以访问管理面"，写进配置而非口头约定。
4. 演练一次完整侦察检测：从扫描开始验证告警。
5. **验证**：模拟扫描必须触发告警；收敛后的端口从外部不可达。
