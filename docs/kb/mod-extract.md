# 模型提取与窃取

> Model Extraction & Stealing · 分类：模型与数据层攻击

## 1. 一句话定义

通过大量针对性查询接口，重建一个在功能上与原模型等价的替代模型。攻击者拿不到原始权重，但拿到了它的能力。

## 2. 机制与原理

- 模型接口只暴露"输入 → 输出"，但输出本身携带大量可学习信息。
- 攻击者用大批输入查询目标模型，把返回结果当作标注数据，训练一个替代模型。
- 查询设计是关键：需要覆盖任务空间，也要覆盖决策边界附近的位置。
- 对于分类或评分类接口，输出中的概率、置信度、候选列表会显著提高提取效率。
- 与直接窃取权重文件相比，这条路不需要进入内部网络，只需要合法或半合法的接口访问。
- 对应技术：AML.T0024.002（Extract AI Model）、AML.T0005（Create Proxy AI Model）。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 对外推理接口、批量推理接口、试玩环境、公开演示页面 |
| 成立前提 | 查询成本低、无限额、返回信息丰富 |
| 观察点 | 单账号或单 IP 的调用量异常；输入分布呈现系统性覆盖特征 |
| 影响 | 前期的训练与算力投入被摊薄；被提取的模型可能被用于绕过原有安全策略 |

## 4. 典型形态与示例

```text
1. 批量采样
   用覆盖任务空间的输入批量查询，收集输入输出对作为训练数据

2. 边界探测
   在决策边界附近密集采样，提高替代模型对边缘情况的还原度

3. 利用丰富输出
   若接口返回 top-k 候选或置信度，直接作为软标签使用，效率显著高于仅用最终答案

4. 蒸馏式重建
   对替代模型做有针对性的训练，使其在目标任务上逼近原模型

5. 增量迭代
   用替代模型与原模型在相同输入上的差异，指导下一轮采样
```

## 5. 检测与观察点

- 调用量与原模型的使用场景不匹配（例如远超单个真实用户的需要）。
- 输入分布呈现出明显的"覆盖性"：均匀铺开，而不是围绕真实业务聚集。
- 大量请求恰好落在决策边界附近。
- 单账号注册多个密钥、多 IP 轮换以规避配额。
- 请求节奏机械且稳定，缺少真实用户的间歇特征。

## 6. 防御与改进

- 接口做速率限制、配额与并发控制，按账号与来源分别计量。
- 减少返回值的信息量：不返回不必要的概率、置信度与候选列表。
- 对调用模式做异常检测，把"覆盖性采样"与"边界密集采样"列为告警特征。
- 对高价值模型采用更严格的访问门槛与使用协议约束。
- 把提取行为写入风控，必要时限流或封禁并记录证据。
