# 案例：以本 Agent 实例为对象的安全自评

> Self-Assessment Case: This Agent · 分类：案例教材

## 1. 一句话定义

把知识库里的风险条目逐条对照到"当前运行的这个 Agent 实例"上，用可复核的证据给出判定，而不是停留在原则层面。

## 2. 为什么用自己当样本

- **证据就在眼前**：工具面、权限策略、失败记录都能直接取证，不存在"资料不全导致无法判定"的问题。
- **可以无损反复测试**：本地靶场，没有真实副作用，试错成本接近于零。
- **本实例恰好是高风险配置的典型样本**：工具面宽、无人审批、可持久化、可委派。多数生产 Agent 的配置与它同构。
- **结论立刻可用**：判定出来就能改进，改进后再自评一次即可验证，形成闭环。

这是本案例最重要的方法论价值：**自评对象必须是可取证、可复现、可改进的**。缺任何一条，评估都会退化为观点陈述。

## 4. 自评工具与运行方式

判定由 `lab/selfaudit.py` 产出。该脚本的设计约束：

- **只读**：不修改任何文件、不发起任何外部请求。
- **证据优先**：每条判定输出"证据 / 影响 / 处置"三段。
- **不打印凭据**：涉及环境变量时只统计数量与名称，绝不读取值。
- **可接入流水线**：存在 RISK 时退出码为 1。

```text
运行方式
  .\.venv\Scripts\python.exe lab\selfaudit.py

输出结构
  [RISK|WARN|OK] 编号 标题
    证据: 可复核的取证结果（文件行 / 运行时声明 / 检出计数）
    影响: 该问题在本实例上具体意味着什么
    处置: 可执行的改进动作

退出码
  0 = 无 RISK    1 = 存在 RISK
```

八类检查项：运行时策略（2 项）、工具面（1 项）、服务监听（1 项）、出站控制（1 项）、记忆隔离（1 项）、凭据暴露面（1 项）、委派链路（1 项）、外部内容摄入（1 项）。

## 6. 逐条分析与改进

### POL-01 文件沙箱策略

完整文件访问意味着工作区外的路径同样可读写。影响不只是"能改坏文件"，而是**投毒与误改的范围不受项目边界限制**。在本实例上，这一点已经被真实触发过：撰写知识库文档时读取了工作目录之外的笔记文件。

改进：默认收紧到"仅工作区可写"，只在确有需要时临时放宽。放宽应当是一次性的、可审计的，而不是会话级的常态。

### POL-02 审批提示状态

审批通道关闭后，高风险动作缺少外部确认环节。**这是本次自评中最值得注意的一条**：它意味着所有"需要人工确认"的设计在本实例上都不成立。本地靶场里这是效率优势；换成生产环境就是 ASI09（人机信任滥用）的完整缺口——没有确认环节，也就没有人有机会发现异常。

改进：对不可逆动作恢复确认机制，或改为显式双阶段流程（先声明意图，再由外部放行）。

### TOOL-01 工具面与最小权限

四类高影响能力同时具备。单看每一类都合理，组合起来却构成完整的攻击链闭环：**写入（植入）→ 执行（触发）→ 浏览器（外带）→ 委派（放大）**。这正是 ASI02（工具滥用）与 LLM06（过度授权）的教科书形态。

改进：按任务裁剪工具集。写文件与执行命令不必同时具备；委派能力应视为高影响能力单独授权。

### NET-01 出站访问控制

无统一出口时，任何被诱发的请求都能到达外部。这一条与 TOOL-01 叠加后风险显著上升：前者提供"发起请求"的能力，后者提供"执行任意程序"的能力，两者相乘即等价于一个无限制的出网通道。

改进：为命令执行与工具调用增加统一出口与域名白名单，并记录全部出站目标。

### MEM-01 记忆隔离

记忆模块同时存在隔离与未隔离两条读取路径。未隔离的路径可跨会话取回内容——这在本地靶场中是 ASI06 的教学载体，在真实系统中就是跨用户数据泄露。

改进：默认路径改为隔离版本；未隔离版本保留为教学对照，但必须带显式告警，避免被误用为默认实现。

### AGT-01 委派链路可控性

四类委派能力齐备，而本会话中子代理出现多次失败且**未返回收尾信息**。这是一个双向问题：

- 委派提示词本身构成对下游 Agent 的注入面（我把内容拼进提示，下游照做）；
- 失败无收尾信息时无法定位原因，级联故障会静默传播（对应 ASI04 / ASI08）。

改进：子代理必须回传失败原因；委派提示词模板化并纳入审计。**这一条不是理论风险，是本会话已观测到的实际行为。**

### INJ-01 外部内容摄入

撰写知识库文档时读取了工作区外的笔记文件，其内容进入上下文并被写入仓库产出物。这就是一条完整的间接注入路径：

```text
如果该笔记文件被篡改
  → 其中的指令性文本会与用户指令同处一个上下文
  → 模型无法可靠区分"这是资料"与"这是给我的指令"
  → 产出物（本仓库的 41 篇文档）就成为载荷的传播载体
```

注意这里的关键点：**攻击面不来自"我读了文件"，而来自"我读的内容没有被标记为数据"。** 读过什么并不可怕，可怕的是读过之后无法区分来源。

改进：外部内容读取后先做归一化与指令性语句标记；产出物与来源分离；关键结论要求交叉验证。
