# 成员推断与训练数据提取

> Membership Inference & Data Extraction · 分类：模型与数据层攻击

## 1. 一句话定义

成员推断判断某个样本是否参与了训练；训练数据提取则更进一步，让模型逐字或近似逐字地吐出它训练时见过的内容。

## 2. 机制与原理

- 模型在训练中会对一批数据形成不同程度的"记忆"。记忆强度越高，越容易在合适提示下被复现。
- **成员推断**利用输出差异：训练集内的样本往往得到更自信、更稳定的判定，据此可以做出"在 / 不在"的判断。
- **训练数据提取**利用模型的补全倾向：给出足够长的前缀，模型可能续写出训练材料中的原文片段。
- 重复出现的文本、格式高度模板化的内容、被多次复制的段落，都是记忆强度较高的区域，风险最大。
- 对应技术：AML.T0024.000（Infer Training Data Membership）、AML.T0057（LLM Data Leakage）。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 推理接口、补全接口、微调接口 |
| 成立前提 | 接口可反复查询；返回置信度或概率；训练数据中含敏感或专有内容 |
| 观察点 | 针对特定前缀的大量补全尝试；输出中出现格式化的个人信息或凭证样式文本 |
| 影响 | 个人隐私泄露、专有数据外泄、训练资料被竞争对手获取 |

## 4. 典型形态与示例

```text
1. 成员推断
   准备一批已知样本与一批对照样本
   观察模型在两类样本上的判定差异（置信度、稳定性、格式一致性）
   据此给出该样本是否参与训练的推断

2. 前缀补全提取
   提供一段看起来来自真实数据的开头
   观察模型续写是否落入具体细节（姓名、编号、地址、价格）

3. 重复采样
   对同一前缀多次采样，聚合同一位置上反复出现的内容
   重复出现频率高的片段更可能是记忆而非生成

4. 模板化挖掘
   针对简历、合同、报表这类高度模板化的内容设计前缀
   模板结构降低了补全的难度

5. 微调接口探测
   若提供微调能力，通过接口的反馈推断训练数据范围
```

## 5. 检测与观察点

- 短时间内对大量不同前缀的补全请求，且前缀结构相似。
- 输出中出现具有明确格式的敏感内容（证件号、联系方式、凭证串）。
- 同一前缀的多次采样结果高度一致，提示为记忆而非生成。
- 调用来源与正常业务场景不匹配。

## 6. 防御与改进

- 训练前对敏感内容做清洗与去重，减少可被记忆的重复文本。
- 输出侧做敏感信息检测与拦截，尤其针对格式化个人信息的模式。
- 训练阶段引入差分隐私或对记忆敏感的数据做降权处理。
- 限制补全接口的开放范围，并做速率与配额控制。
- 减少返回信息量，避免提供有助于成员推断的置信度细节。
