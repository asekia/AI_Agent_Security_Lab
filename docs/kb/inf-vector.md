# 向量数据库枚举

> Vector Database Enumeration · 分类：AI 基础设施与供应链

## 1. 一句话定义

向量数据库往往默认无认证、对外开放，枚举它可以得到集合结构、向量维度与元数据——这些信息足以推断出业务范围与所用嵌入模型。

## 2. 机制与原理

- 向量库是 RAG 系统的核心存储。它的接口设计以"方便检索"为目标，认证常被当作后置事项。
- 可枚举的信息分三层：
  - **结构层**：有哪些集合、各自的向量维度、距离度量方式。
  - **内容层**：集合中的向量数量、元数据字段。
  - **语义层**：从元数据与维度推断业务领域与所用嵌入模型。
- 向量维度是重要线索：不同嵌入模型的维度不同，维度值可以直接指向模型系列。
- 元数据字段名会暴露业务结构，例如客户标识、文档类型、时间戳、租户编号。
- 对应技术：AML.T0085.000（Data from AI Services: RAG Databases）。

## 3. 攻击面与前提

| 组件 | 默认端口 | 可识别特征 |
| --- | --- | --- |
| Qdrant | 6333 / 6334 | 6333 提供 HTTP 接口，6334 为 gRPC |
| Weaviate | 8080 | REST 与 GraphQL 接口 |
| Milvus | 19530 | gRPC 接口 |
| Chroma | 8000 | HTTP 接口 |

成立前提：接口可达，且未启用认证或使用了默认配置。

## 4. 典型形态与示例

```text
枚举流程（概念演示）
1. 识别组件类型与版本
2. 列出集合名称，观察命名规律（是否包含业务或租户标识）
3. 读取集合配置，记录向量维度与距离度量
4. 统计向量数量，评估数据规模
5. 查看元数据字段名，推断业务结构
6. 由维度值反推嵌入模型，评估其版本与能力

信息价值
  集合名       → 业务划分与租户结构
  向量维度     → 所用嵌入模型
  向量数量     → 数据规模与增长情况
  元数据字段   → 业务字段与可能的敏感属性
  距离度量     → 检索行为特征，影响可构造的检索竞争

本页内容仅用于本地靶场与已授权评估。
```


### 各产品的枚举端点

| 产品 | 端点 | 返回内容 |
| --- | --- | --- |
| Weaviate | `GET /v1/meta` | 服务器版本与已安装模块 |
| Weaviate | `GET /v1/schema` | 全部类定义：属性名 + 向量化模块配置——`vectorizer` 字段直接说明所用嵌入模型 |
| Qdrant | `GET /collections` | 全部集合名 |
| Qdrant | `GET /collections/{name}` | 向量维度、距离度量、总点数 |
| Chroma | `GET /api/v1/collections` | 旧版本默认无认证直接返回集合列表 |

未认证的 Weaviate 实例更进一步：schema 查询与数据查询全套可用。

### 一个读懂枚举结果的例子

一个名为 `internal-hr-policies` 的集合、768 维、50,000 个点——三条信息足以还原出：该 RAG 系统索引的是内部 HR 政策文档、嵌入模型是 768 维输出（典型如 BERT / sentence-transformers 系）、语料规模约 5 万条。攻击者还没有读到任何一条文档内容，系统画像已经基本成型。

## 5. 检测与观察点

- 向量库端口是否对外可达，是否启用认证。
- 是否存在来自外部的结构枚举特征：连续请求集合列表与配置接口。
- 集合命名是否泄露租户或业务信息。
- 元数据中是否包含敏感字段。

## 6. 防御与改进

- 向量库启用认证与授权，按租户划分命名空间并强制隔离。
- 服务只对内部网络开放，不直接暴露到外网。
- 最小化元数据字段：不写入与检索无关的业务标识。
- 关闭不必要的枚举类接口，限制集合列表的可见范围。
- 监控结构枚举行为并对异常来源告警。
