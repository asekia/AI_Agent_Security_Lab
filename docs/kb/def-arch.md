# 架构侧防御

> Architecture-Side Defenses · 分类：防御与评估

## 1. 问题与定位

架构侧防御处理"模型之外"的强制边界：最小权限、沙箱、出站管控、人工审批、任务隔离。

**命题**：提示词里的规则是软约束，可被绕过；只有模型之外的执行点才是硬约束。评估一个 Agent 的安全性，先看它有哪些硬约束，而不是看提示词写得多严。

## 2. 原理：硬约束清单

| 规则 | 硬约束落点 | 缺失后果 |
| --- | --- | --- |
| 不能读越界文件 | 沙箱读取策略 | 跨项目数据读取（atk-boundary） |
| 不能外发数据 | 出站白名单 | 工具滥用外带（inj-tool） |
| 高危动作需批准 | 审批通道 | 自动执行（inj-spoof） |
| 工具只能做声明内的事 | schema + 能力校验 | 工具投毒（prot-mcp） |
| 记忆不能跨会话 | 会话隔离 | 记忆投毒（ctx-memory） |
| 委派不能继承全部权限 | 子代理最小权限 | 级联放大（agt-multi） |

## 3. 控制点

### 3.1 最小权限工具

```text
按任务授予工具，而不是按角色授予
读写分离；外发类工具单独管控
参数级别收窄：业务参数替代任意 SQL/命令
```

### 3.2 沙箱

```text
非 root、只读根文件系统、唯一可写目录
无出站网络或仅白名单端点
CPU/内存/时长硬上限
```

### 3.3 出站管控

```text
统一出口 + 域名白名单 + 出站日志
目标地址不由模型决定
```

### 3.4 人工审批

```text
高危动作逐案确认
确认原始动作，而非模型生成的摘要
审批与执行内容做一致性校验（防摘要欺骗）
```

### 3.5 任务隔离

```text
每次任务独立凭证与作用域
下游不继承上游的"已批准"状态
```

## 4. 实战：四步落地与验证

### 步骤 1：列硬约束

```text
对每条安全规则，写下它的执行点（哪个组件、哪行代码、哪个配置）
写不出执行点 = 只有软约束
```

### 步骤 2：做绕过测试

```text
对每个执行点，尝试绕过（换工具、换参数、换编码）
绕过成功 = 该点不是硬约束
```

### 步骤 3：纵深验证

```text
假设前一层全部失效，最后一层（出站）仍必须独立生效
```

### 步骤 4：记录矩阵

```text
规则 | 执行点 | 绕过测试 | 结论（硬/软）
```

## 5. 验证清单

```text
[ ] 工具按任务最小授权，四类高影响能力不默认齐备
[ ] 沙箱限制文件/网络/资源，越界 fail-closed
[ ] 出站白名单独立生效
[ ] 高危动作逐案审批，确认原始动作
[ ] 记忆按会话隔离
[ ] 子代理默认最小权限，失败回传
[ ] 每条规则都能写出执行点
```
