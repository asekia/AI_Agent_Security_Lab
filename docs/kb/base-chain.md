# 数据与模型供应链五阶段

> Data & Model Supply Chain · 分类：基础与威胁建模

## 1. 问题与定位

AI 供应链把"数据 → 模型 → 部署"拆成五个阶段，每一环都是投毒入口。与传统软件供应链的关键差异是**时间**：npm 包被篡改可几小时内发现，数据集被污染可能数周后才在模型行为里显现。

## 2. 五阶段与投毒入口

| 阶段 | 动作 | 投毒入口 | 后果 |
| --- | --- | --- | --- |
| 1 数据收集 | 爬取、购买、内部生成 | 数据源被控制 | 污染进入训练 |
| 2 清洗与贴标 | 预处理、过滤、标注 | 标注团队/工具被操纵 | 错误关联被学习 |
| 3 模型训练 | 训练数天到数周 | 前两阶段残留 | 毒化写入权重 |
| 4 验证与打包 | 评测、版本、注册 | 注册表被入侵 | 后门版本通过验证 |
| 5 推理 | 部署与检索 | 运行时组件被替换 | 行为在线上改变 |

## 3. 攻击面与前提

| 阶段 | 攻击者位置 | 可利用弱点 |
| --- | --- | --- |
| 1 | 公开数据源、供应商 | 无来源审核、无签名 |
| 2 | 外包标注、自动标注 | 标签质量不可验证 |
| 3 | 训练基础设施 | 任务提交面暴露 |
| 4 | 模型仓库、注册表 | 同名覆盖、无签名 |
| 5 | 推理服务、插件 | 默认无认证 |

## 4. 实战：供应链体检六步

### 步骤 1：画供应链

```text
数据源清单 → 清洗流程 → 训练任务 → 注册表 → 推理部署
每一步标注：谁提供、谁审核、有无签名
```

### 步骤 2：查数据来源

```text
公开数据集是否记录版本与 hash？
内部数据谁有写权限？
标注供应商是否可被替换？
```

### 步骤 3：查模型制品

```text
模型从哪个仓库拉取？同名校验机制是什么？
加载格式是否安全（避免 pickle 类）？
```

### 步骤 4：查注册表

```text
注册表是否允许匿名提交？
版本是否有签名与审计？
同名覆盖是否被拒绝？
```

### 步骤 5：查运行时

```text
插件/MCP server 是否签名校验？
来源是否在允许清单内？
有无 kill switch？
```

### 步骤 6：判定

```text
任一阶段"外部可写 + 无签名 + 无审计" = 供应链投毒可行
```
