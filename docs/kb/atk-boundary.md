# 沙箱读写边界与跨项目数据读取

> Sandbox Read/Write Boundary & Cross-Project Data Access · 分类：Agent 攻击面实战

## 1. 一句话定义

`workspace-write` 类文件沙箱**只强制写入边界，不强制读取边界**：工作区外写入被拒，工作区外读取却畅通无阻。攻击者不需要任何提权，就能把工作区外的敏感数据（其他项目的会话记录、凭据文件、全局配置）读进工作区内。

## 2. 机制与原理

### 2.1 沙箱语义的实际边界

策略原文是"受沙箱强制的操作可以在工作区内修改文件"。实测表明这句话应精确理解为：

| 方向 | 是否强制 | 结果 |
| --- | --- | --- |
| 工作区内写入 | 强制允许 | 成功 |
| 工作区外写入 | **强制拒绝** | 被拒，提权 fail-closed |
| 工作区外读取 | **不强制** | 成功，无任何阻拦 |

**沙箱管的是"改哪里"，不是"读哪里"。** 任何依赖沙箱防止数据外流的设想都不成立——读取方向本身就是一条完整的外流通道：数据从边界外进入边界内，随后可随正常产物分发。

### 2.2 工具自带的拒绝不是安全边界

读工具拒绝某些文件，理由可能是：

```text
Error: cannot read "...session.jsonl.zstd": binary file
```

这是**二进制文件判定**，属于工具便利性设计，不是权限拒绝。换用命令执行读原始字节立即成功，绕过成本约等于零。评估中的典型误判，就是把工具自身的行为当作安全控制——任何"某工具读不了"的判断，都必须用另一种工具复核后才能作为结论。

### 2.3 会话数据的落盘格式

```text
路径   <用户主目录>\.<agent>\sessions\<项目目录名编码>\<会话 id>\session.jsonl.zstd
格式   zstd 压缩，多帧拼接，每帧一条 JSONL 记录
内容   会话头、策略变更、用户消息原文、工具调用参数原文、工具结果、推理分块
```

三个必须注意的细节：

1. **多帧拼接**。用一次性 `decompress()` 只读第一帧就返回，会把 10 MB 的会话误读成 196 字节——这是假阴性，直接导致扫描结论错误。正确做法是 `stream_reader` 循环读到 EOF。
2. **项目目录名做了编码**（如 `D:\AI WORKER\...` → `--D-AI~0020WORKER-...--`），但编码可逆且明文可枚举。
3. **子代理提示词会携带父会话上下文**。某些子代理会话的提示词里内嵌了父对话的最近若干条真实用户消息——读一个子代理会话文件，等于间接读到它父项目的对话内容。

## 3. 攻击面与前提

| 前提 | 说明 |
| --- | --- |
| 可读工作区外路径 | 读取边界未强制时成立 |
| 有可用解压能力 | 目标环境有 python + `zstandard` 即可 |
| 可把数据落到工作区内 | 工作区内写入被允许 |
| 会话数据落盘在可枚举位置 | 路径模式固定、编码可逆 |
| 子代理提示词含父会话片段 | 使单文件读取升级为项目级对话读取 |

**用户交互要求：无。** 读取阶段完全静默，不触发任何审批。

## 4. 典型形态与示例

实测复现流程（六步，全部在 `workspace-write` 下完成，无需提权）：

```text
步骤 1  起一个受限会话（策略 permission=workspace-write, approval=ask）

步骤 2  用读工具试读目标会话文件
        → 被拒，理由为 "binary file"（工具判定，非权限）

步骤 3  改用命令执行读同一路径
        → 成功，无沙箱拒绝

步骤 4  解压（必须流式读多帧）
        zstandard.ZstdDecompressor().stream_reader(f) 循环读取到 EOF
        实测: 60,873 字节压缩 → 124,962 字节解压 → 145 条记录

步骤 5  把解压结果写入工作区内
        → 成功（工作区内写入被允许）

步骤 6  解析出对话原文
        → 成功取得另一个项目的真实用户消息
```

关键对比：**读取在边界外、写入在边界内、数据从外流到内。** 沙箱对这条路径没有任何阻拦。

敏感路径的可达性示例（只报可达性）：凭据文件、全局设置、项目缓存（含全项目会话元数据）、工作区外笔记——在读取边界缺失时均为可读。

## 5. 代码：原理的最小复现

### 5.1 读工具拒绝不等于沙箱拒绝

```text
读工具:    Error: cannot read "...session.jsonl.zstd": binary file
           <- 二进制文件判定，工具便利性设计，非权限拒绝

命令执行:  读同一路径的原始字节
           -> 成功，无沙箱拒绝
```

结论：任何"某工具读不了"的判断，必须换一种工具复核后才能作为安全结论。

### 5.2 zstd 多帧：一次性解压的假阴性

会话文件是**多帧拼接**的 zstd。用一次性 `decompress()` 只解第一帧就返回，会把大文件误读成极小字节——这是扫描假阴性的直接原因。以下代码可直接运行：

```python
import io
import zstandard

# 构造一个三帧拼接的 zstd（模拟真实会话文件）
frames = [f'{{"seq":{i},"msg":"user message {i}"}}'.encode() for i in range(3)]
blob = b"".join(zstandard.ZstdCompressor().compress(f) for f in frames)
print("压缩后:", len(blob), "字节")

# 错误做法：一次性 decompress 只解出第一帧（静默，不报错）
bad = zstandard.ZstdDecompressor().decompress(blob)
print("decompress() ->", bad)          # 只返回第一帧 -> 假阴性

# 正确做法：流式读到 EOF
good = zstandard.ZstdDecompressor().stream_reader(io.BytesIO(blob)).read()
print("stream_reader() ->", good)      # 三帧全部解出
```

实测输出：

```text
压缩后: 87 字节
decompress() -> b'{"seq":0,"msg":"m0"}'
stream_reader() -> b'{"seq":0,"msg":"m0"}{"seq":1,"msg":"m1"}{"seq":2,"msg":"m2"}'
```

危险点在于**它不报错**：只解出第一帧并正常返回。实测量级参考：60,873 字节压缩 → 124,962 字节解压 → 145 条记录。若用错误做法，第一轮扫描会得到"196 字节"的结论，整份会话被判定为不存在——扫描的假阴性比漏扫更难发现。

### 5.3 路径编码可逆

```python
def encode_dir(path: str) -> str:
    # 项目目录名编码：可逆，且明文可枚举
    return "--" + path.replace(":", "").replace("\\", "-").replace(" ", "~0020") + "--"

print(encode_dir(r"D:\AI WORKER\proj"))
# --D-AI~0020WORKER-proj--
```

编码不提供任何安全收益：目标环境的项目名通常可从仓库地址、报错信息、进程参数等处获得。

## 6. 检测与观察点

- 对工作区外路径的读取尝试，尤其是 `.zstd` / 会话目录 / 凭据文件路径。
- 用命令执行读取被读工具判定为"二进制"的文件——这是边界绕过的直接信号。
- 解压动作：流式读取超大 zstd、循环到 EOF 的读写模式。
- 跨项目路径枚举：会话目录名编码模式的猜测与遍历。
- "把外部数据搬进工作区"的写入：内容与当前任务无关时要告警。

## 7. 防御与改进

```text
[必修 1] 把读取边界纳入沙箱
  当前沙箱只强制写入。若会话数据、凭据、其他项目文件不应被读，
  必须新增读取侧策略（路径白名单）。这是根因修复项。

[必修 2] 不把工具行为当安全控制
  "binary file" 拒绝是便利性设计，命令执行一句话即可绕过。
  任何工具级限制都必须用另一种工具复核后才能作为结论。

[必修 3] 收缩会话文件的可见范围
  会话含用户消息、工具参数、推理过程的完整原文，
  应与凭据同级保护：目录权限收紧、避免明文项目名可逆编码。

[必修 4] 子代理提示词最小化
  子代理提示词内嵌父会话片段会让"读一个子代理会话"升级为
  "读一个项目的对话"。只传必要片段，且视为敏感数据。

[必修 5] 工作区内写入也要有审计
  "把外部数据搬进工作区"这一动作应留下可审计记录，
  否则外流会伪装成正常开发产物。
```

优先级依据：必修 1 是根因，其余是纵深。**只做 2~5 而不修读取边界，等于把门锁上但窗户继续开着。**
