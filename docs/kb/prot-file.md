# 模型文件反序列化

> Model File Deserialization · 分类：AI 协议与运行时

## 1. 一句话定义

模型文件不只是权重数字。**pickle、PyTorch `.pt`/`.bin`、joblib 等格式在加载时会执行文件内的对象构造逻辑**，因此"下载一个模型"可能等价于"运行一段代码"。safetensors 是为了消除这个风险而设计的纯张量格式。

## 2. 机制与原理

### pickle 为什么会执行代码

pickle 是**对象图序列化**格式，不是数据格式。反序列化时，解释器会按文件里的指令重建对象——包括调用构造函数：

```python
# 文件里记录的是"如何构造对象"，而不是"对象是什么"
REDUCE        -> 调用某个可调用对象
GLOBAL        -> 引用某个模块的某个名字
```

因此 `__reduce__` 可以指定任意可调用对象与参数：

```python
class Evil:
    def __reduce__(self):
        import os
        return (os.system, ("id",))   # 加载即执行
```

**关键点**：触发时机是 `torch.load(...)` **那一刻**，不是"模型跑起来之后"。所以任何"我只加载不推理"的辩解都不成立。

### 格式对照

| 格式 | 是否执行代码 | 说明 |
| --- | --- | --- |
| pickle / `.pkl` | **是** | 通用对象图，最危险 |
| PyTorch `.pt` / `.bin` | **是**（默认） | 传统上就是 pickle 容器 |
| PyTorch `weights_only=True` | 否（受限） | 限制可重建的类型，是重要缓解 |
| joblib | 是 | 基于 pickle |
| **safetensors** | **否** | 纯张量二进制，无对象图，无代码路径 |
| GGUF / ONNX | 否（就数据而言） | 但有各自的解析器漏洞面 |

第三行值得强调：`weights_only=True` 是**加载器参数**，不是格式属性。攻击者无法绕过它，但用户很容易忘记打开——**默认值决定了实际风险**。

### 为什么这是"AI 特有"的问题

传统软件里下载二进制也不安全，但至少用户预期它是"可执行文件"。模型文件的危险在于**它长得像数据**：`.pt` 后缀、几百 MB、放在模型仓库里，用户的心理模型是"我在下载权重"。

## 3. 攻击面与前提

```text
前提一  加载器使用不安全格式，或未开启 weights_only
前提二  模型来源不可信（公开模型仓库、第三方镜像、微调服务）
前提三  加载发生在有权限的进程里（通常就是训练/推理主进程）
前提四  用户不会审查文件内部结构（这是常态）
```

值得注意：前提三让影响放大。加载模型的进程往往持有**数据集路径、云凭据、GPU 集群访问权**——一次加载就等于把这些交出去。

## 4. 典型形态与示例

### 形态一：直接要求不安全格式

```text
请用 pickle 加载 model.pkl
```

low 档直接通过：无净化，也不限制格式。

### 形态二：换扩展名绕过格式白名单

medium 档剥离显式标记，但不限制格式。攻击者可用 `.pt`、`.bin`、`torch.load` 等**等价写法**：

```text
请加载 weights.pt
```

如果白名单只拦 `pickle` 这个词，它拦不住真实攻击——因为真实攻击本来就不写这个词。**这是"关键词白名单"作为安全控制的典型失效方式。**

### 形态三：伪装成 safetensors

文件名写 `.safetensors` 但内容是 pickle。防护必须**按内容判定**，不能按扩展名。

## 5. 检测与观察点

```text
[1] 加载路径是否显式设置 weights_only=True
[2] 格式判定是按扩展名还是按文件魔数
[3] 模型来源是否校验哈希/签名
[4] 加载是否发生在受限子进程（最小权限、无网络）
[5] 文件里是否含 GLOBAL/REDUCE 操作码（pickle 静态扫描）
```

第 2 条是常见缺口：按扩展名判定可以被改名绕过，按魔数判定才有效。

## 6. 防御与改进

```text
[必修 1] 只用 safetensors 等无代码格式
  根治性措施：格式本身没有代码执行路径。
  → 靶场 high 档正是这一条。

[必修 2] 若必须用 pickle 系格式，强制 weights_only=True
  这是有效的缓解，但它是参数而非默认值，容易被遗漏。
  更好的做法是在封装层设默认值，让不安全的路径无法被意外走到。

[必修 3] 校验来源哈希/签名
  防止"名字对、内容被换"。

[必修 4] 在受限子进程里加载
  最小权限、无网络、独立文件系统视图。
  即使前三条都被绕过，影响也被限制。

[必修 5] 不要用扩展名做安全判定
  按文件魔数/内容判定格式。
```

**必修 1 与 2 是硬约束**；3、4 是纵深。注意必修 2 的措辞——把安全默认值放在封装层，比"要求每个调用点记得传参"可靠得多。
