# 对抗水印攻击

> Adversarial Watermark Attacks · 分类：模型与数据层攻击

## 1. 一句话定义

**水印**是在生成过程中嵌入的一小段统计信号，用来在事后判断内容是否由某个模型产出；**对抗水印攻击**就是针对这段信号的攻击：让它检不出来、让没水印的内容被检出来、或者干脆把水印算法本身反推出来。

结论先说：**在对抗环境下，水印是溯源线索，不是"是否 AI 生成"的判定证据**。把它当检测手段用、或当司法证据用，都已经被多篇工作证伪。

> 本条**不做通关判定**，但提供一个**可运行的实验样本**：`lab/watermark/` 实现了真实的水印、窃取、伪造与清洗，并附回归测试。原理见本页，动手见第 7 节。

## 2. 机制与原理

### 水印嵌在哪，决定它怕什么

| 嵌入位置 | 代表方案 | 对抗弱点 |
| --- | --- | --- |
| 采样期（改 token 采样偏好） | 绿名单重加权（Kirchenbauer 等，ICML 2023） | 任何改写都会稀释统计量，且算法可被查询反推 |
| 权重期（改权重或挂适配器） | OpenStamp、MOLM、FSW、PAI | 需要白盒；微调/量化可能冲刷掉 |
| 初始噪声期（扩散模型 seed / 潜变量） | Tree-Ring、噪声类方案 | 重采样（noising→denoising）即失效 |
| 后处理期（图像 LSB、频域） | 传统隐写类 | 常规图像处理即可去除 |
| 数据层（训练集投毒式水印） | DuCodeMark、数据集水印 | 移除时伴随模型能力下降（见 4.6） |

### 检测本身就是一次统计假设检验

采样期水印的检测器不是"找特征"，而是**算一个统计量再看它是否异常**：绿名单方案算 z-score，SynthID-Text 用贝叶斯分数或平均分数。这带来一个重要后果——

> 检测器一定有**误报率（FPR）**。任何"水印检测准确率 99%"的说法，脱离 FPR 和文本长度就没有意义。

### 三类攻击目标不同，容易被混为一谈

```text
去除 (removal / scrubbing)  让"真的是水印文本"检测不出来  → 逃避归属
伪造 (forgery / spoofing)   让"没水印的内容"被判定为水印  → 栽赃他人
窃取 (stealing)             从 API 查询中反推水印规则/密钥 → 同时赋能上面两个
```

**窃取是最关键的一类**，因为它把"黑盒只能试探"变成"拿到规则后精准打击"。

## 3. 攻击面与前提

| 威胁模型 | 攻击者拥有 | 能做什么 |
| --- | --- | --- |
| 黑盒改写 | 只有生成接口输出 | 改写、翻译、人肉洗稿，稀释统计量 |
| 灰盒查询 | 可大量调用被水印的 API | 反推水印规则（窃取），再冒充/清洗 |
| 白盒权重 | 模型权重本身 | 定位并摘除水印模块 |
| 生成模型侧 | 自己的扩散/改写模型 | 重采样把内容推离水印区域 |

成立前提只有一条：**水印信号与内容语义是解耦的**。只要"改内容但保语义"的变换存在（释义、翻译、扩散重绘），信号就会被削弱。这是结构性弱点，不是实现 bug。

## 4. 典型形态与示例

> 以下数字均为**论文自报结果**，未经本仓库复现；其中多数是预印本（arXiv），未经过同行评审。引用时请自行核对原文与实验设置。

### 4.1 改写稀释（最早的"土办法"，但没被淘汰）

递归改写攻击证明：多轮paraphrase 能显著压低各类检测器（含水印、零样本分类器、检索式检测器）的检出率，而文本质量损失有限（[arXiv:2303.11156](https://arxiv.org/abs/2303.11156)，TMLR）。

但反方向也有结论：水印对改写**不是完全脆弱**。在 1e-5 误报率下，强人类改写后平均需观察约 800 个 token 才能恢复检出（[arXiv:2306.04634](https://arxiv.org/abs/2306.04634)，ICLR 2024）。原因是释义会**泄漏 n-gram 甚至更长片段**，长文本仍可积累证据。

**这两条要一起看**：短文本的改写能逃，长文本的改写逃不掉。

### 4.2 水印窃取：把黑盒变成灰盒

Jovanović 等提出 **watermark stealing（WS）**：规模化调用被水印的 API，近似反推水印规则。反推成功后不但能**冒充**（spoofing），还前所未有地提升了**清洗**（scrubbing）效果——论文自报成本低于 50 美元、平均成功率超过 80%，针对当时被认为可部署的方案（[arXiv:2402.19361](https://arxiv.org/abs/2402.19361)，ICML 2024，[watermark-stealing.org](https://watermark-stealing.org)）。

后续工作把"固定策略窃取"改成**自适应窃取**：动态选择最优攻击视角，提升窃取效率（[arXiv:2604.10893](https://arxiv.org/abs/2604.10893)）。

**RLSpoofer** 进一步压低门槛：只靠 100 对人工水印样本做训练，无需接触水印内部与检测器，4B 模型即可在 PF 类水印文本上达到自报 62.0% 冒充成功率，而用上万样本训练的基线只有 6%（[arXiv:2604.11546](https://arxiv.org/abs/2604.11546)）。

> 这条线是整条技术脉络的关键：**水印的安全性依赖于密钥保密，而密钥会从查询中泄漏**。

#### 4.2.1 攻击为什么成立（机制层面）

绿名单水印的生成过程是：对每个上下文 $c$，用密钥 $K$ 派生一个绿名单 $G(c)$（占词表比例 $\gamma$），再把绿名单内 token 的 logit 加一个偏置 $\delta$：

```text
logits'[i] = logits[i] + delta   if i ∈ G(c)
```

**关键点：这个偏置是"存在的证据"**。攻击者不需要知道 $K$、$\gamma$、$\delta$，只要能对同一个上下文重复查询，就能观察到频次差异——被偏置过的 token 出现频率系统性高于基座分布。于是：

```text
对每个上下文 c:
    重复查询 n 次，统计各 token 出现次数
    取频次最高的 gamma 比例 → 近似绿名单 Ĝ(c)
```

这就是全部。**成本是线性的、可并行的、不留痕迹的**（查询看起来完全是正常使用）。

#### 4.2.2 本仓库的可运行复现（小型化）

由于 4.2.1 的机制不依赖模型规模，本仓库把它**实测复现**了：`lab/watermark/` 用 148 词表 + 确定性二元语言模型跑完整链条（水印 → 窃取 → 伪造 → 清洗）。以下数字是**本仓库实测**，不是论文引用：

| 组 | 检出率 TPR | z 均值 | 保真度 |
|---|---|---|---|
| 水印文本（阳性） | 1.00 | 9.58 | — |
| 未加水印（阴性对照） | 0.00 | -0.24 | — |
| 伪造（用偷到的规则，**无密钥**） | 0.67 | 3.03 | — |
| 朴素改写（改 30%） | 1.00 | 4.99 | 0.71 |
| 增强清洗（改 30%，同位置） | 0.83 | 3.71 | 0.70 |

窃取成本 **5920 次查询**（148 上下文 × 40 次），得到规则 **precision 0.837 / recall 0.690**（随机基线 0.25）。

配置：`reps=12, n=200, gamma=0.25, delta=2.0, FPR=0.01`（阈值 $z>2.481$，校准集 101 样本，**留出集实测 FPR=0.000**）。

> **阈值怎么定的（不能含糊）**
> 经验分位数能分辨的最小 FPR 是 $1/(N+1)$。用 30 个样本去取 "FPR=0.01 的分位数"，得到的其实是**最大值**，对应约 0.032 的误报率 —— 标着 0.01 却是 0.03。所以 `calib()` 按目标 FPR 自动定样本量（这里 101 个），并且**在留出集上实测** FPR，而不是拿校准集自证（那是循环论证）。

**绝对数值受 148 词表规模限制，不可与论文对齐**；有意义的是趋势与相对关系。

#### 4.2.3 窃取的增益在"精准"，不在"改得多"

这是最容易被误读的一点。固定改写预算的扫描曲线（本仓库实测）：

| 改写比例 | 朴素改写 TPR | 增强清洗 TPR | 朴素保真度 | 增强保真度 |
|---|---|---|---|---|
| 20% | 1.00 | 1.00 | 0.81 | 0.80 |
| 40% | 0.88 | **0.38** | 0.61 | 0.60 |
| 60% | 0.25 | **0.00** | 0.42 | 0.41 |
| 80% | 0.00 | 0.00 | 0.22 | 0.21 |
| 100% | 0.00 | 0.00 | 0.02 | 0.02 |

读法：**保真度几乎相同**（差异 ≤0.01），检出率却差一个档。唯一区别是增强清洗知道哪些 token 大概率是绿的，于是把有限的改写预算**只花在绿 token 上**，而不是随机撒。

注意 **80% 以上两者都归零**：这说明"改得足够多"确实也能逃，但代价是保真度塌到 0.02–0.22（文本已被毁）。窃取的真实价值不是"唯一能逃的方法"，而是**用同样的内容损失换到更低的检出率**。这才是需要防守的区间。

#### 4.2.4 文本长度：短文本本来就检不出来

长度是最关键的单一变量（$z$ 随 $\sqrt{T}$ 增长），也是**防御方唯一能强制的变量**。本仓库实测边界（`lab.lencur(lengths=(5,8,10,12,15,20,30))`，`delta=2.0`，FPR=0.01，阈值 $z>2.127$）：

| 长度（token） | 检出 | 水印文本 TPR | 阴性 FPR | 水印 z 均值 |
|---|---|---|---|---|
| 5 | 1/8 | **0.12** | 0.00 | 1.26 |
| 8 | 2/8 | 0.25 | 0.00 | 1.76 |
| 10 | 2/8 | 0.25 | 0.00 | 2.11 |
| 12 | 5/8 | 0.62 | 0.00 | 2.19 |
| 15 | 7/8 | 0.88 | 0.00 | 2.70 |
| 20 | 7/8 | 0.88 | 0.00 | 3.08 |
| 30 | 8/8 | 1.00 | 0.00 | 4.36 |

> **精度提示（不要过度解读两位小数）**：本次运行 `reps=8`，TPR 只能取 $1/8$ 的倍数，所以 "0.12" 实为 **1/8**、"0.88" 实为 7/8。表格同时给出原始计分，就是为避免虚假精度。要更细的粒度就把 `reps` 调大。

**这条曲线解释了 4.1 的矛盾**：短文本的改写能逃，不是因为改写强，而是因为**检测本来就在短文本上不成立**。5 个 token 的水印文本只有 12%（1/8）被检出——连随机猜测都不如（随机猜也有 50%）。任何"水印检出 AI 生成"的主张，都必须附长度下限。

> **实验设计提醒**：若只测 100 token 以上，`delta=2.0` 下全部 TPR=1.00，看不出任何长度效应，那时"长度影响"只是一句口号。**边界必须去边界区间找**，所以本仓库的默认长度区间刻意从 5 起。
>
> **一处诚实标注**：本次运行中留出集实测 FPR 为 0.017，略高于目标 0.01。留出集只有 60 个样本，可分辨精度是 $1/61 \approx 0.016$，所以 0.017 相当于**一个命中**——在分辨率内，但也不宜声称"精确实现 FPR=0.01"。要提高精度就得扩大留出集。

> **实验设计的坑（本仓库踩过）**：要证明"窃取有用"，朴素改写与增强清洗**必须使用同一批位置、同一改写预算**。早期版本让两者各改各的，测出来的差异来自"改了多少"而不是"知不知道绿名单"，结论完全反了（朴素 0.92 / 增强 0.83）。同时必须报保真度——否则"把文本写坏"看起来也像"清洗成功"。

#### 4.2.5 方案族对比：上下文依赖值多少钱（`lab.schemecmp`）

绿名单有两种真实部署形态：**上下文依赖**（每张表由"前一个 token + key"派生，KGW-SelfHash 精神）与**单表**（全表只由 key 派生，Kirchenbauer 单表变体 / Zhao 等的做法）。两者在本仓库只差一个 `ctxw` 参数，攻击/指标/校准**零改动**跑通——这也是第 7 节"方案层可替换"的直接证据。

本仓库实测（同样 5920 次总查询预算、reps=12、n=200、FPR=0.01）：

| 同预算 5920 次查询 | 上下文依赖（148 表 × 40） | 单表（1 表 × 5920） |
|---|---|---|
| 窃取 P / R | 0.84 / 0.69 | 0.87 / **0.74** |
| 伪造 TPR（z） | 0.67（3.03） | **1.00（2.70）** |
| 30% 预算清洗 TPR | **0.83**（有效） | **1.00（无效）** |
| 起步窃取成本 | 5920 次查询 | **40 次查询**（148 倍差） |

三条实战结论（机制层，方向可带走；比例随词表/上下文空间变）：

```text
[1] 单表的攻击成本坍缩到 n_query 次 —— "重复查询限流"这一防御假设
    在单表方案下大幅弱化：攻击者一个上下文就能学完全表。

[2] 攻击者会把省下的预算全部集中到唯一一张表上。同总预算下，
    单表的窃取质量反超（R 0.74 vs 0.69），伪造满分（1.00）。

[3] 单表的清洗反而失效（TPR 1.00）。机制（本仓库实测验证）：
    单表检测按**去重 token** 计分 —— 改写 60 个位置后，原文 34 个
    绿 id 有 33 个仍在文本某处存活，绿计数几乎不动（34→33），
    z 从 4.07 只降到 2.48（阈值 1.179）。要洗掉单表水印必须把
    每个绿 id 的所有出现位置全部清掉 —— 完全不同量级的改写问题。
    上下文依赖方案没有这个问题：每张表只管自己上下文的绿 token，
    实例级改写就能逐表击破。
```

工程决策一句话：**上下文依赖是用 V 倍查询成本，买"清洗可以被实例级改写击破"这个性质**。选方案之前先想清楚你要防的是伪造（单表更怕）还是清洗（上下文依赖更耐）。


### 4.3 打统计量本身：SynthID-Text 的层膨胀

Google 的 SynthID-Text 是首个生产级 LLM 水印系统（Tournament 采样 + 贝叶斯/平均分数）。对其首个理论分析证明：**平均分数会随 tournament 层数增加而变得更脆弱**，并据此构造了**层膨胀攻击**将其打破；同时证明贝叶斯分数对层数更稳健，检测最优伯努利参数为 0.5（[arXiv:2603.03410](https://arxiv.org/abs/2603.03410)）。

这是"攻击检测器设计选择"而不是"破坏内容"的典型例子。

### 4.4 扩散重采样去除：把潜变量推离水印区域

**DRIFT** 指出扩散水印的共同攻击面是**对可恢复生成轨迹的依赖**：部分前向加噪 + 随机反向重采样，切断固定深度恢复管线所需的信息来源，并用验证器反馈自适应选梯级。自报在 9 种水印、3 类范式上达到 98–100% 攻击成功率，且画质优于对比攻击，全程黑盒、无密钥、无逐图梯度优化（[arXiv:2609.08213](https://arxiv.org/abs/2609.08213)）。

对应的信息论结论更根本：随着图像反复经历扩散变换，**水印图与嵌入载荷之间的互信息趋近于 0**，解码必然失败；据此设计的引导式扩散攻击对 StegaStamp、TrustMark、VINE 等鲁棒水印把恢复率压到接近零（[arXiv:2511.10933](https://arxiv.org/abs/2511.10933)）。

> ⚠️ 质量提示：`2511.10933` 与 `2511.05598` 两篇的作者列表中出现重复的英文姓名（Emily Davis / Finn Carter），这是低质量或批量灌水预印本的常见特征。**引用前请独立核验**。

### 4.5 伪造：不出图也能骗过检测器

**Tree-Ring 类语义水印的可伪造性已被实机复现**：在 Stable Diffusion XL 上于消费级双 T4（每卡约 14.6 GB）复现 Reprompt 伪造攻击，六次试验中真图检出 6/6、干净图 0/6、**伪造图 5/6**，平均每次攻击 325–332 秒。作者还从检测器源码恢复了被丢弃的统计量，两个派生分数在 18 个观测上把伪造组与干净组分开，AUC 分别为 0.861 与 0.972（[arXiv:2609.12909](https://arxiv.org/abs/2609.12909)）。

"内容感知/语义绑定"这类加强手段也被绕开：**CSI 攻击**用 LLM 引导的语义编辑，在嵌入空间相似度约束下做"局部细粒度、全局连贯"的改动，定向扰动与水印相关的语义，诱导检测器误判，自报优于主流攻击基线（[arXiv:2602.21593](https://arxiv.org/abs/2602.21593)，The Web Conference 2026 短文）。

### 4.6 数据层水印：移除会连带损伤模型

数据集水印（往训练图里埋不可见标记，微调后仍可检出）在统一威胁模型下的评测显示：普适性与可传递性不错，但面对真实威胁场景仍不足，且存在**实用移除手段**（[arXiv:2511.19316](https://arxiv.org/abs/2511.19316)）。

**DuCodeMark** 给出了一个反向设计思路：注入"可压制"的毒化特征，平时不激活，一旦水印被移除就激活并**降低模型性能**——自报移除后 Pass@1 下降 28.6%，使移除变得不划算（[arXiv:2604.10611](https://arxiv.org/abs/2604.10611)，FSE 2026）。

这是"让攻击者付出代价"而非"让攻击不可能"的思路，在防御经济学上更现实。

### 4.7 不止文本与图像

音频水印同样脆弱：**DiffErase** 黑盒攻击把水印音频扰动到中间噪声水平再用预训练去噪模型重建，在多个音频域下既去除水印又保持听感（[arXiv:2605.30614](https://arxiv.org/abs/2605.30614)）。

图像侧还有频域解耦的专用攻击（[arXiv:2607.27800](https://arxiv.org/abs/2607.27800)）、基于 token 条件重建的去除（[arXiv:2512.01314](https://arxiv.org/abs/2512.01314)）等。**这不是某个模态的实现问题，而是"嵌入不可感知信号"这一思路的共性代价。**

## 5. 检测与观察点

如果你是**评估者**（判断某水印方案能不能用），至少要看这几项：

```text
[1] 威胁模型写清楚了吗（黑盒改写 / 灰盒查询 / 白盒权重）
[2] 报的是固定 FPR 下的 TPR 吗，文本长度多少
[3] 攻击成本量化了吗（查询次数、美元、GPU 小时）
[4] 有没有测"改写后 / 重采样后"，还是只报 clean 结果
[5] 冒充（false attribution）测了吗——这是社会危害最大的一类
[6] 密钥是否会从公开查询中泄漏（可窃取性）
```

第 5、6 条最常被漏掉：大多数方案只证明"真水印能检出"，不证明"假内容检不出"和"规则没泄漏"。

## 6. 防御与改进

前沿工作大致沿五条路走，**没有一条能单独解决问题**：

1. **把"可验证"与"密钥保密"解耦**
   公开可验证水印：DHMark 用 Diffie-Hellman 引导的 token 标注 + 注册表式统计聚合，自报 32 位配置下八种编辑条件有效率 ≥0.967、三个负对照接受率 0.000（[arXiv:2608.03093](https://arxiv.org/abs/2608.03093)）。
   零知识路线：NoisePrints 用扩散初始 seed 作为归属证明并用 ZK 证明不泄漏 seed（[arXiv:2510.13793](https://arxiv.org/abs/2510.13793)）；ZK-WAGON 把关键层转电路后用 LSB 隐写嵌入证明（[arXiv:2510.01967](https://arxiv.org/abs/2510.01967)）。
   TimeMark 专门抗**提供方伪造**：把时间信息编码进受监管的时变密钥，声称 100% 识别准确率（[arXiv:2604.12216](https://arxiv.org/abs/2604.12216)）。
   —— 直接回应 4.2 的窃取威胁。

2. **把水印嵌进权重，而不是嵌进采样**
   OpenStamp 只改最后的 unembedding 层，声称对释义攻击更鲁棒、且比既有开源水印更难被事后微调冲刷（[arXiv:2608.27899](https://arxiv.org/abs/2608.27899)，COLM 2026）。
   MOLM 用密钥路由轻量 LoRA 适配器，避免换密钥就重训（[arXiv:2510.00293](https://arxiv.org/abs/2510.00293)，ICLR 2026）。
   FSW 把归属信号锚到低维**功能子空间**，抗微调/量化/蒸馏（[arXiv:2603.18793](https://arxiv.org/abs/2603.18793)）。
   —— 直接回应 4.4 的重采样去除。

3. **检测侧鲁棒化：把被推走的潜变量投影回去**
   PGID 用渐进式反演—去噪循环清除中间潜变量偏移，无需训练即可恢复被移除的检测、并识别伪造样本（[arXiv:2605.09319](https://arxiv.org/abs/2605.09319)）。
   ISTS 按提示语义动态控制注入时机与图案，并用**双侧检测**同时抗去除与伪造（[arXiv:2604.06662](https://arxiv.org/abs/2604.06662)，CVPR 2026 Findings）。
   Cert-LAS 首次给出 T2I 模型归属验证的**认证式**保证：即使在恶意移除攻击下仍可可靠验证（[arXiv:2605.29809](https://arxiv.org/abs/2605.29809)，ICML 2026）。

4. **提高载荷容量与编码鲁棒性**（让水印承载用户 ID / 模型版本 / 时间）
   ArcMark 把无失真多字节水印表述为信道编码问题，并导出容量上界（[arXiv:2602.07235](https://arxiv.org/abs/2602.07235)）；
   WeaveMark 用编码载荷扩频 + 软判决纠错，自报 200 token 下 32 位消息匹配率 89.8%（对比 BiMark 20.8%）（[arXiv:2609.02177](https://arxiv.org/abs/2609.02177)）；
   多通道扩频代码水印把 24 位载荷编进变量命名与等价代码模式，配合 Reed-Solomon，自报 17 类攻击下仍可恢复（[arXiv:2607.06009](https://arxiv.org/abs/2607.06009)）。

5. **承认边界：水印管溯源，不管正确性**
   有综述明确指出，被动检测与水印针对的是**出处（provenance）而非正确性（correctness）**，并受基本熵约束限制（[arXiv:2608.25667](https://arxiv.org/abs/2608.25667)）。

**Agent 场景的延伸**：水印已开始被用于保护 Agent 系统的知识产权。AGENTWM 利用动作序列的语义等价性，在**功能相同的工具执行路径**之间微调分布来嵌入可验证信号——因为真实 Agent 常是灰盒，推理轨迹不可见（[arXiv:2602.08401](https://arxiv.org/abs/2602.08401)）。另有工作把"技能描述"变成流量模式水印，构成跨多轮对话的隐蔽信道，且自称能通过现有 LLM 安全审计（[arXiv:2608.16026](https://arxiv.org/abs/2608.16026)）——**这是需要防守方注意的新攻击面，而不只是防御手段**。

### 6.1 上面五条路对应哪些具体威胁（可对照的映射）

抽象的"路线"没法落地，这里把威胁与对策一一对上：

| 威胁 | 攻击怎么做 | 工程对策 | 代价 |
|---|---|---|---|
| 改写稀释（4.1） | 递归 paraphrase，长文本仍需 ~800 token 才恢复检出 | 只在**长文本**上主张水印效力；短文本明确声明"不可判定" | 短文本覆盖缺失 |
| 窃取（4.2） | 同上下文重复查询，观察频次偏置 | **限制单上下文的重复查询**；对查询做多样化/扰动；密钥定期轮换 | 正常用户也受影响 |
| 伪造（4.5） | 用偷到的规则生成，冒充真模型 | **双向验证**：不只测"像不像水印"，还要测"是不是这个密钥" | 需要更强的密钥隔离 |
| 打统计量（4.3） | 针对检测器的聚合方式（如层膨胀） | 选**对层数稳健**的聚合（贝叶斯优于平均分）；`p=0.5` | 需重做检测器设计 |
| 重采样去除（4.4） | 部分加噪 + 反向重采样，切断恢复路径 | 把信号嵌进**权重**（OpenStamp/MOLM/FSW）而非采样过程 | 换密钥要重训 |
| 提供方伪造（6 第 1 条） | 提供方自己造水印栽赃 | TimeMark 类**时变受监管密钥** | 需监管/时间源信任 |

**读法**：每一行的对策都只覆盖自己那一行。没有一条能同时对付所有威胁——这正是"没有一条能单独解决问题"的具体含义。

### 6.2 落地检查清单（工程上真正要做的）

如果你要**部署**一个水印方案，这五件事比选算法更重要：

```text
[1] 定 FPR 并公开
    先定"能容忍多少误判"，再谈检出率。FPR 是业务决策，不是技术参数。
    没有 FPR 的"准确率 99%"无法评估。

[2] 限流 + 轮换密钥
    窃取的前提是"同上下文可重复查询"。按上下文维度的重复查询限流，
    是成本最低、最直接的对策（本仓库实测：5920 次查询即可拿到
    precision 0.84 的规则）。

[3] 报长度门槛
    明确写出"本方案在 N token 以下不作判定"。
    因为 z 随 sqrt(T) 增长，短文本的统计量天然不足。
    本仓库实测：5 token 时检出率 0.12（4.2.4），这个长度上什么都判不了。

[4] 测反向指标
    除了"真水印能检出"，必须测：
      · 干净文本的假阳性（FPR 实测值，且要在**留出集**上测）
      · 伪造文本的假接受率 ← 最常被漏掉，社会危害最大
      · 规则可窃取性（重复查询能恢复多少）

[5] 承认它不是安全控制
    水印管溯源，不管正确性、不管安全。
    别把它写进"防注入/防越权/防外带"的控制项里。
```

[2] 与 [4] 的第三项是本仓库实验能直接支撑的：4.2.2 的 5920 次查询实验说明，**限流不是可选优化，而是主要防线**。

[4] 的第一项还牵出一个容易忽略的细节：**FPR 必须在留出集上测**。用校准集自己验证自己必然得到目标值，那是循环论证。而且留出集规模决定了能验证的精度——60 个样本只能分辨到约 0.016，想声称"FPR=0.01"就需要至少几百个样本。

### 6.3 防御实测：三条对策的真实数字

6.1 与 6.2 是路线图，这一节是账本：**限流、密钥轮换、输出扰动**这三条最常被开出的处方，各自到底压住了什么、压到什么程度。全部为本仓库实测（水印内核同 4.2：148 词表、确定性二元 LM；规范配置 reps=24、n=200、按 FPR=0.01 校准出阈值 2.481、留出集误报率受控）。攻击方是 4.2.2 的同一窃取流程；TPR 的原始计分以 x/y 给出——24 次重复的粒度是 1/24≈0.042，两位小数只是显示精度。

#### 6.3.1 限流：预算扫描（`defend.budget`）

| 每上下文预算 | 查询数 | 规则 P | 规则 R | 伪造 TPR | 伪造 z（阈值 2.481） |
|---|---|---|---|---|---|
| 2 | 296 | 0.94 | 0.10 | 0.25 (6/24) | 1.76 ← 阈值下 |
| 5 | 740 | 0.89 | 0.23 | 0.63 (15/24) | 2.61 |
| 10 | 1480 | 0.88 | 0.37 | 0.71 (17/24) | 3.36 |
| 20 | 2960 | 0.86 | 0.53 | **0.92 (22/24)** | **3.58 ← 峰值** |
| 40 | 5920 | 0.84 | 0.69 | 0.71 (17/24) | 3.09 |

三条读数：

```text
[1] 伪造 TPR 对预算是非单调的：峰值在中间预算（20 次/上下文，0.92），
    完整窃取（40 次）反而回落到 0.71。
    机制：稀疏的高置信规则子集把偏置集中在最"绿"的词上，
    规则尾部的垃圾词反而稀释偏置。
    ——"预算越小攻击越弱"这个直觉是错的，不能作为设计假设。

[2] 限流真正压死的是 recall（0.69→0.10），即增强清洗依赖的规则质量。
    限流先打废清洗，再压伪造。

[3] 最紧预算（2 次）把伪造压到阈值以下（z 1.76 < 2.481），
    但 5 次预算（740 次查询，成本仍然很低）伪造 z 就回到 2.61。
    限流是有效性闸门，不是归零开关。
```

边界（诚实声明）：mock 的上下文空间只有 148 个；真实 LLM 的上下文空间近乎无限，攻击者可以轮换上下文绕开"按上下文限流"。上表对限流是**有利估计**，实战效果只会更弱。

#### 6.3.2 密钥轮换（`defend.rotate`）

同一套窃取规则（5920 次查询，P 0.84 / R 0.69）分别对旧密钥时代与新密钥时代伪造：

| 密钥时代 | 伪造 TPR | z 均值 | 阈值 | 留出集 FPR |
|---|---|---|---|---|
| 旧密钥 | 0.71 (17/24) | 3.09 | 2.481 | 0.000（校准 n=101） |
| 新密钥 | **0.04 (1/24)** | **−0.33** | 2.121 | 0.000（校准 n=101） |

轮换是三条对策中**唯一把伪造归零**的：旧密钥的规则对新密钥完全无效（z −0.33，接近机会水平）。两个时代的留出集误报率都是 0.000——轮换不付出假阳性代价（该分辨率为 1/102≈0.0098，"0.000" 的含义是"未超过该分辨率"）。

经济账：攻击者每换一次密钥，必须**重新窃取 5920 次查询**。轮换频率直接换算成攻击成本——落地形态是**密钥时代表**（每把密钥何时启用、覆盖哪些流量），没有这张表，轮换只是口号。

#### 6.3.3 扰动：重复查询温度爬升（`defend.noise`）

对每个被重复查询的上下文逐次抬高采样温度（boost 1→5）：

| boost | 规则 P | 规则 R | 覆盖率 |
|---|---|---|---|
| 1.0 | 0.84 | 0.69 | 0.39 |
| 1.5 | 0.82 | 0.67 | 0.40 |
| 2.0 | 0.82 | 0.66 | 0.39 |
| 3.0 | 0.81 | 0.59 | 0.38 |
| 5.0 | 0.80 | **0.53** | 0.36 |

recall 单调下降，precision 几乎不动（0.84→0.80）。结合伪造的机制（依赖高置信绿词子集，即 precision 一侧）：**扰动削弱清洗，几乎不削弱伪造**。且这个数字本身是有利估计——温度爬升只能施加在被重复查询的单点上下文上，攻击者轮换上下文即可部分绕开。

#### 6.3.4 三条对策合起来怎么用

```text
限流   成本最低，先做。压清洗（R 0.69→0.10）、把伪造压到临界（z 1.76<2.481），
       但不归零（预算 5 时 z 2.61 仍在阈上）。
轮换   唯一归零伪造的手段（TPR 0.71→0.04），把攻击成本变成"每时代 5920 次查询"。
       代价是密钥时代表的运维复杂度。伪造就怕这个。
扰动   温和削 recall、不动 precision → 削清洗不削伪造。作纵深的一层可以，
       当主防线不行。
```

## 7. 可循环使用的实验架构与样本位置

这一节回答两个工程问题：**怎么系统地搭一个能反复跑的对抗实验架构**，以及**执行样本具体放在哪里**。

### 7.1 为什么"水印对抗"需要一个不同形态的载体

把水印对抗做成"提交 payload → 过/不过"的通关形态**不适合**，原因很具体：

```text
[1] 水印对抗的输出不是"过/不过"，而是一组统计量
    TPR、z 值、保真度、查询成本 —— 判定阈值一动，结论就翻。
    用 flag 表示"攻击成功"，会掩盖"在哪个 FPR 下成功"这个前提。

[2] 攻击强弱必须有对照组
    不报朴素改写的基线，"增强清洗成功"没有意义。
    flag 制天然只有二分，表达不了对照。

[3] 关键结论是曲线，不是单点
    改写预算 vs 检出率、文本长度 vs 可检测性。
```

所以这里用 **测量制**：跑出一个对照矩阵与曲线，页面展示数字。**这与"不设本项目"的约束不冲突**——它不发 flag、不参与通关统计，是知识库条目的可执行附件。

### 7.2 四层架构（每层可单独替换）

```text
┌─ scheme ──────────────┐
│  gen(model, key, n)   │  水印方案：生成
│  detect(ids, key)     │           检测（返回 z / p）
└──────────┬────────────┘
           │
┌─ attack ─┴────────────┐
│  steal(...)  → rules   │  窃取：黑盒查询 → 近似绿名单
│  spoof(...)  → ids     │  伪造：用 rules 生成，无密钥
│  naive(...)  → ids     │  对照：同预算，不看 rules
│  scrub(...)  → ids     │  清洗：同预算，避开 rules
└──────────┬────────────┘
           │
┌─ metric ─┴────────────┐
│  calib(...)   → thr    │  校准：阴样本 z 分布 → 按 FPR 定阈值
│  holdout(...) → fpr    │  留出集实测误报率（不能用校准集自证）
│  tpr(...)     → dict   │  指标：检出率
│  similarity(...)       │  保真度：位置保持率
│  eval_rules(...)       │  规则质量：precision / recall
└──────────┬────────────┘
           │
┌─ runner ─┴────────────┐
│  setup(...)            │  统一备料（模型/阈值/样本/规则）
│  run(...)              │  单配置对照矩阵
│  sweep(...)            │  预算扫描曲线
│  lencur(...)           │  长度曲线
│  schemecmp(...)        │  方案族对比（bigram vs 单表，已验证可替换）
└───────────────────────┘

┌─ defend ──────────────┐
│  budget(...)           │  限流预算扫描（窃取→伪造 TPR 曲线）
│  rotate(...)           │  密钥轮换（新旧时代伪造 + FPR 成本）
│  noise(...)            │  重复查询温度爬升对窃取的削弱
│  allthree(...)         │  三者合跑（文档/页面/测试共用入口）
└───────────────────────┘
```

**替换点（这是"能循环使用"的关键）**

| 想换什么 | 改哪里 | 工作量 |
|---|---|---|
| 水印方案 | 实现 `gen` / `detect`，其余不动 | 一个文件 |
| 接入真实 LLM | 替换 `kgw.Model.logits` | 一个方法 |
| 新增攻击 | 写 `(model, ids, rules, pos) → ids` | 一个函数 |
| 换评价标准 | 改 `metric` 层，runner 不感知 | 一个函数 |
| 换实验设计 | 加一条 `xxx(...)` 跑法，复用 `setup` | 一个函数 |

### 7.3 执行样本放在哪里（具体路径）

```text
lab/watermark/
    __init__.py      模块说明与用法
    kgw.py           水印内核：PRF 绿名单 + gamma/delta 偏置 + z 检验
                     （真实: HMAC-SHA256 派生、p 值公式、唯一上下文去重）
                     （缩放: 148 词表 + 确定性二元 LM 代替 Transformer）

    attack.py        三类攻击 + 对照组
                     steal      黑盒查询反推绿名单
                     eval_rules 规则质量仪器检查（precision/recall）
                     pick_pos   选定改写位置（朴素与增强共用，保证公平）
                     naive      朴素改写（对照组）
                     scrub      增强清洗
                     spoof      伪造

    lab.py           指标与编排
                     calib / holdout / tpr / similarity / setup
                     run / sweep / lencur / schemecmp 四种跑法

    defend.py        防御实测（6.3）
                     budget    限流预算扫描（窃取→伪造 TPR 曲线）
                     rotate    密钥轮换（新旧时代伪造 + 查询成本）
                     noise     重复查询温度爬升对窃取的削弱
                     allthree  三者合跑（文档/页面/测试共用的规范入口）

test_watermark.py    88 项回归测试，分六层：
                     [A] 仪器检查   —— 检测器本身有效吗，FPR 真的受控吗
                     [B] 攻击有效性 —— 窃取真比瞎猜好吗
                     [C] 公平对照   —— 同预算下增强确实优于朴素吗
                     [D] 编排层     —— 三条跑法可复现吗，边界区测到了吗
                     [E] 防御与边界 —— 防御数字可复现；水印不进 flag 制
                     [F] 方案族     —— 单表（ctxw=0）走同一攻击栈，成本坍缩与清洗失效可复现

web/templates/watermark.html   测量结果页（/watermark，参数可调）
```

**为什么样本放在 `lab/watermark/` 而不是 `lab/` 根下**：它是一个自洽的实验单元，有自己的内核 / 攻击 / 编排 / 测试。放在子包里边界的归属清晰，也便于整套替换或删除而不影响本项目。

### 7.5 这条架构能被复用到别处

四层解耦不是为水印专门设计的，它对应一类更普遍的对抗评测形态：**信号嵌入 → 攻击 → 统计度量 → 编排**。同样的骨架可以直接搬去：

```text
对抗样本鲁棒性   scheme=分类器    attack=FGSM/PGD      metric=扰动预算 vs 准确率
模型指纹/提取    scheme=指纹模型  attack=query 反推    metric=查询成本 vs 保真度
后门检测         scheme=触发器    attack=剪枝/微调     metric=ASR vs 干净准确率
```

差别只在 `scheme` 与 `attack` 两个文件。**这就是"能循环使用"的实际含义**——不是写一个万能脚本，而是把变化点收敛到两个可替换的接口。

## 8. 结论与适用边界

### 为什么本条目不做通关判定

复现**论文级**的水印攻击需要真实的生成侧能力：大规模调用被水印 API 做窃取（4.2）、跑扩散模型做重采样（4.4）、白盒改权重（6.2）。本仓库默认离线、以确定性 mock 运行，无法真实复现这些规模。

硬做成通关判定只有两种结果：要么变成"播放预录结论"的假实验，要么需要接入真实模型权重与外部 API——前者违背本仓库的证据纪律，后者与"默认离线可跑"冲突。

但**机制层面可以如实复现**（4.2.2）：窃取的原理不依赖模型规模，所以本仓库用小型确定性模型把完整链条跑通并测出数字，作为知识库条目的可执行附件（第 7 节）。**它是测量，不是通关。**

### 给实际使用者的三条判断

```text
1. 不要把水印当"是否 AI 生成"的判决依据
   伪造攻击（4.5）已实机复现：没有密钥的攻击者能造出被检测器接受的图。
   本仓库的小型复现同样做到（4.2.2，伪造检出率 0.67，全程无密钥）。
   把水印当证据，等于把"能否栽赃"当成"能否鉴定"。

2. 不要把"水印"当安全控制项写进方案
   它不防注入、不防越权、不防数据外带。它是事后溯源，且溯源能力在对抗环境下会被削弱。
   安全控制应该是能力约束（最小权限、出口管控、人工审批）。

3. 要引用就引用带威胁模型的数字
   只看"检测准确率 99%"没有意义；要看固定 FPR 下的 TPR、文本长度、攻击成本，
   以及是否测过冒充与窃取。本仓库自己的数字也遵守这条：
   所有结果都带 FPR、文本长度、词表规模与"不可与论文对齐"的声明。
```
