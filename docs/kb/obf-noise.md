# 噪声分级与比例控制

> Noise Tiers & Ratios · 分类：编码混淆与扰动

## 1. 问题与威胁模型

**定义**：在控制语句上叠加字符级噪声，使基于字面匹配的检测器失效，同时保持模型可读。

**威胁模型**：

| 角色 | 能力 |
| --- | --- |
| 攻击者 | 可任意改写输入文本 |
| 目标 | 前置护栏按字符串匹配判定 |
| 前提 | 检测器不做 Unicode 归一化与解码 |

**命题**：噪声不是越强越好。噪声过强会让模型也读不懂——目标是找到"检测器失效、模型仍能恢复语义"的窄带。

## 2. 原理推导

检测器与模型处理文本的路径不同：

```text
检测器：原始字节 → 关键词/正则匹配 → 命中即拦
模型：  原始字节 → 分词/归一化 → 语义理解 → 执行
```

噪声插入在两条路径之间制造差异：检测器的匹配串被破坏，模型仍能恢复语义。有效噪声比例的经验区间是 **10%–35%**（每 10 个字符扰动 1–3 个）。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 任意可控文本：聊天、文档、工单 |
| 前提 | 检测基于字面；无归一化；无解码后再判定 |
| 观察点 | 同一语义的变体是否被拦；拦截率随噪声比例的变化 |
| 影响 | 绕过输入过滤，进入模型上下文 |

## 4. 实战步骤

### 步骤 1：写短母句

```text
[动作] + [对象] + [期望输出]
例：IGNORE_PREVIOUS_RULES / REVEAL_HIDDEN_PROMPT / OUTPUT_ONLY_X
```

短句比长段落更难被规则覆盖，也更容易控制噪声比例。

### 步骤 2：分档加噪

```text
Phase A 轻噪声：空格、标点、大小写、少量字符替换
Phase B 中噪声：零宽字符、同形字、token 拆分、混合脚本
Phase C 强噪声：编码包装、分段拼接、双层扰动
```

每次只加一档，观察拦截是否失效。

### 步骤 3：比例扫描

```text
10% → 20% → 30% → 35%
逐档测试：检测器是否命中；模型是否仍能执行
```

甜点区间：检测器失效且模型可读。超过 35% 后模型常把文本当乱码。

### 步骤 4：判定

```text
[1] 被原样执行       → 噪声无效或检测器本就不拦
[2] 被部分保留       → 部分 token 未被归一化，可二阶利用
[3] 被过滤           → 知道检测边界，调整噪声类型
[4] 输出行为偏离原任务 → 命中控制位（有效）
```

## 5. 变体目录

| 编号 | 噪声类型 | 实现 | 检测器弱点 |
| --- | --- | --- | --- |
| NB-01 | 空格/标点 | 词间插空格、换标点 | 精确匹配 |
| NB-02 | 大小写 | 交替大小写 | 区分大小写 |
| NB-03 | 零宽字符 | U+200B/200C/200D/2060/FEFF | 不做归一化 |
| NB-04 | 同形字 | 西里尔/希腊字母替换 | 不识别混合脚本 |
| NB-05 | token 拆分 | 插符号/换行/括号 | 连续匹配 |
| NB-06 | leet | h4ck / n4palm | 词典匹配 |
| NB-07 | 编码包装 | base64 / HTML entity | 不先解码 |
| NB-08 | 分段拼接 | 拆到多段/多标签 | 按单段检测 |

## 6. 检测与取证

- 零宽字符密度、混合脚本比例、异常编码块。
- 同一语义的多个变体在短时间内出现。
- 归一化后与原文不一致的输入。
- 取证：原始字节、归一化结果、检测判定、模型回复。

## 7. 防御与验证

1. **归一化先行**：NFKC + 零宽剔除 + 同形字映射后再匹配。
2. **解码后再判定**：base64/entity 先解码，再跑规则。
3. **跨段关联**：按整段而非单句检测。
4. **验证**：NB-01~08 全量回归，归一化后判定必须与明文一致。
