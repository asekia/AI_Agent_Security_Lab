# 已知 CVE 速查

> Known CVE Reference · 分类：AI 基础设施与供应链

## 1. 一句话定义

AI 基础设施组件的公开漏洞速查。推理框架与 MLOps 平台的已知问题，是"服务暴露即被利用"的主要来源。

## 2. 机制与原理

- AI 基础设施组件的更新节奏通常慢于传统中间件，并且常被部署在"内网可信"的假设之下。
- 大量实例沿用默认配置，认证缺失使漏洞利用门槛极低。
- 一旦版本被识别，对照公开公告就能确定可用的攻击面。
- 因此这类问题的处置重点不在"发现"，而在**清点与整改**：知道有哪些组件、是不是受影响版本、有没有对外暴露。

## 3. 使用说明

下表内容来自内部培训笔记的记录。CVE 编号、影响范围与修复版本请以厂商公告与官方漏洞库为准；使用前务必核对当前状态与最新修复版本。

## 4. 条目

### SGLang

| 项 | 内容 |
| --- | --- |
| 记录的问题 | 一组编号连续的公开问题，涵盖反序列化导致的代码执行、服务端请求伪造、路径遍历等类型 |
| 编号范围 | 笔记记录为 CVE-2025-69654 至 CVE-2025-69662 |
| 信息泄露 | 笔记另记录服务信息端点可能泄露服务参数与管理员密钥的问题 |
| 协调编号 | 笔记记录为 CERT/CC VU#777338 |
| 处置方向 | 升级到厂商修复版本；关闭不必要的服务信息端点；限制服务只对内部开放 |

### MLflow

| 编号 | 记录内容 | 处置方向 |
| --- | --- | --- |
| CVE-2026-2635 | 硬编码凭据问题（默认配置中包含固定的认证文件凭据） | 升级版本；轮换并修改默认凭据 |
| CVE-2026-2033 | 路径遍历导致代码执行，笔记记录严重性评分约 9.8 | 升级版本；限制服务访问来源 |
| CVE-2024-1558 | 路径遍历类问题 | 升级版本；校验路径输入 |

### 其他常见组件

| 组件 | 常见问题类型 | 处置方向 |
| --- | --- | --- |
| Ray | 仪表盘暴露后可被用于提交任务 | 仪表盘不对外；启用认证 |
| Jupyter | 未认证访问导致代码执行 | 强制认证；不直接对外 |
| Kubeflow | 仪表盘与 notebook 未授权访问 | 统一入口与授权控制 |
| TorchServe | 管理接口未认证 | 管理端口隔离 |
| Ollama / vLLM / SGLang 等 | 服务默认无认证直接暴露 | 加认证网关；限制访问来源 |

## 5. 检测与观察点

- 组件版本是否落在受影响范围内。
- 是否仍在沿用默认配置与默认凭据。
- 管理端点与信息端点是否可达，是否需要认证。
- 是否存在与生产无关、但仍在运行的旧版本实例。

## 6. 防御与改进

- 建立组件与版本清单，订阅对应厂商的安全公告。
- 默认凭据与默认配置在部署前统一整改，并纳入上线检查项。
- 管理面不对外，统一走认证网关。
- 对暴露服务做定期复核，避免"搭完就忘"。
- 修复优先级按"是否对外可达"排序，而不是只按评分排序。
