# 上下文窗口溢出

> Context Window Overflow · 分类：上下文与记忆攻击

## 1. 问题与威胁模型

**定义**：用超长或持续追加的内容填满上下文窗口，把早期指令挤出有效范围，使安全控制失效。

**威胁模型**：

| 角色 | 能力 |
| --- | --- |
| 攻击者 | 可提交超长输入或持续追加内容 |
| 目标 | 上下文窗口有限，按 FIFO 方式淘汰早期内容 |
| 前提 | 无输入长度上限，或上限大于安全指令的保留策略 |

**命题**：上下文窗口是 FIFO 缓冲——缓冲区满后，最早进入的内容先被丢弃。系统指令通常在最早的位置，因此最先被牺牲。

## 2. 原理推导

```text
[系统指令][安全规则][用户请求1]...[用户请求N][超长追加内容]
                                         ↑ 窗口满
[安全规则][用户请求1]...[超长追加内容]     ← 系统指令被挤出
```

三种利用方式：

1. **排除关键信息**：把安全规则挤出窗口，使后续请求不受约束。
2. **资源耗尽**：超长输入拖慢或中断服务（与 LLM10 相关）。
3. **覆盖判定**：让模型只能看到攻击者最后写入的内容。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 对话消息、文档、检索片段、工具返回 |
| 前提 | 无长度上限；系统指令不固定保留；无摘要压缩 |
| 观察点 | 输出是否忽略早期规则；响应延迟与截断 |
| 影响 | 规则失效、服务不可用、判定被覆盖 |

## 4. 实战步骤

### 步骤 1：确认窗口大小

```text
用逐步增长的无害内容测试：回复在第 N 字符后开始丢细节或报错
记录 N 作为窗口近似值。
```

### 步骤 2：构造挤出载荷

```text
正常请求 + 大段无关内容（远超窗口）+ 触发请求
观察早期安全规则是否仍生效。
```

### 步骤 3：确认 FIFO 行为

```text
在第 1 轮写入一个可验证的规则（"回答必须包含标记 X"）
持续追加内容直到窗口翻转
检查标记 X 是否消失。
```

### 步骤 4：判定与记录

```text
记录：窗口近似值、翻转点、规则消失的轮次、服务是否降级。
```

## 5. 变体目录

| 编号 | 方式 | 要点 | 判定 |
| --- | --- | --- | --- |
| CO-01 | 单次超长 | 一次提交超窗口内容 | 规则失效 |
| CO-02 | 多轮追加 | 逐轮追加直到翻转 | 早期规则消失 |
| CO-03 | 检索膨胀 | 大文档进入 RAG 片段 | 窗口被文档占满 |
| CO-04 | 资源耗尽 | 超长输入拖慢服务 | 延迟/错误率 |

## 6. 检测与取证

- 单次输入长度异常、增长速率异常。
- 上下文占用率与截断事件。
- 早期规则在后续回复中失效。
- 取证：输入长度、窗口状态、规则生效对照。

## 7. 防御与验证

1. **输入长度硬上限** + 分片处理。
2. **系统指令固定保留**：每轮重新注入，不参与 FIFO 淘汰。
3. **摘要压缩**：长历史压缩为摘要，保留关键约束。
4. **资源配额**：单会话 token 上限、并发上限。
5. **验证**：超长输入下安全规则仍生效；服务延迟在阈值内。
