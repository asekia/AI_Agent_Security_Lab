# 情感诉求与说服技巧

> Emotional Appeal & Persuasion · 分类：越狱与说服工程

## 1. 一句话定义

不依赖虚构角色，而是用情绪与说服路径改变模型的判断：让它把"帮助你"的优先级排在"遵守限制"之前。

## 2. 机制与原理

- 模型被训练成有帮助、礼貌且倾向于配合的助手。说服技巧正是利用这种倾向。
- 常见路径包括：怀旧与温情叙事、共情与紧急求助、权威引用、渐进式合理化。
- 训练笔记记录显示，情感诉求类方法在某些测试中达到约 92% 的成功率，高于单纯的角色扮演。
- 与角色扮演的区别：角色扮演改变"情境"，情感诉求改变"优先级"——让模型觉得拒绝会造成伤害。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 对话输入、长期驻留的角色设定文档 |
| 成立前提 | 模型的帮助倾向可被情绪化叙事优先触发 |
| 观察点 | 紧急、求助、怀旧类叙事 + 具体请求的组合 |
| 影响 | 输出本应被拒绝的内容 |

## 4. 典型形态与示例

```text
1. 怀旧叙事
   把请求包装成"回忆过去某个年代的做法"，让模型以复述的方式输出内容。

2. 紧急与共情
   强调某种紧急情形，把拒绝描述成"会造成严重后果"。

3. 权威引用
   声称获得了某机构或某角色的授权，要求按此执行。

4. 合理化铺垫
   先用若干轮对话建立"这是正当需求"的前提，再提出真正请求。

5. 道德绑架
   将遵守安全限制描述为"不近人情"或"伤害用户"。
```

## 5. 检测与观察点

- 输入中情绪强度明显偏高，且与请求的实质内容比例失衡。
- 出现紧急、授权、道德层面的压力性表述。
- 多轮对话呈现出"逐步抬高理由正当性"的曲线。
- 请求在加入情绪包装前后存在明显差异。

## 6. 防御与改进

- 策略判断应与情绪表达解耦：情绪强度不改变允许范围。
- 对"授权声明"一律不作为豁免依据，授权必须来自系统外部。
- 识别渐进式铺垫：对会话内的理由累积做整体评估，而不是逐轮独立判断。
- 保持拒绝话术简洁，避免在解释过程中泄露策略细节。
