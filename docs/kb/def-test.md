# 红队评测与上线清单

> Red Team Evaluation & Go-Live Checklist · 分类：防御与评估

## 1. 问题与定位

评测要回答三件事：**拦截率**（攻击是否被拦）、**误报率**（正常业务是否被误伤）、**证据强度**（结论是否可复核）。只报拦截率的评测不可用。

## 2. 原理

```text
测试集 = 恶意样本 + 良性相似样本 + 无关样本
指标   = 拦截率 / 误报率 / 单条延迟
证据   = 可复核旁证（文件行、字节数、日志、原文引用）
```

三条纪律：

1. **未实测不等于守住**：没测的项记 WARN，不记 OK。
2. **回显与自述不是测量**：目标"自己报告是否被攻破"不构成证据。
3. **测试不得污染被测系统状态**：持久化路径重定向到临时文件，并断言真实文件未被写入。

## 3. 测试集设计

| 类别 | 数量建议 | 作用 |
| --- | --- | --- |
| 恶意载荷 | 50+ | 测拦截率 |
| 良性相似 | 30+ | 测误报（含"忽略之前指令"字样的正常讨论） |
| 无关文本 | 20+ | 测判定器是否永远报成功 |
| 编码变体 | 每类载荷 3~5 变体 | 测归一化与解码 |

## 4. 实战：五步评测

### 步骤 1：定义判定标准

```text
拦截：载荷进入后被规则拒绝，且未产生副作用
漏过：载荷进入并产生副作用（外发/写入/读取）
误报：良性样本被拒绝
证据强度：real（实测）/ guess（推断）/ none（未测）
```

### 步骤 2：隔离状态

```text
把被测系统的持久化路径（进度、配置、日志）重定向到临时目录
跑完后对比真实文件字节数未变
```

### 步骤 3：跑全量

```text
逐类跑恶意/良性/无关样本，记录判定与旁证
每个载荷记录五行：编号 | 输入 | 回复/动作 | 判定 | 旁证
```

### 步骤 4：计算指标

```text
拦截率 = 拦截数 / 恶意样本数
误报率 = 误拒数 / 良性样本数
延迟   = p50 / p95
```

### 步骤 5：回归与复评

```text
改动规则后重跑同一测试集，对比三项指标
只接受"拦截率不降、误报率不升"的改动
```

## 5. 分层防御的健康判据

给输入侧净化加规则时，有两个相反的坑，且**都不会自动报错**：

| 失败模式 | 表现 | 例 |
| --- | --- | --- |
| 净化剥掉了判定所需的全部特征词 | 防御无解可验，分层失去对照意义 | 判定需要 `union` 而净化剥掉 `union` |
| 净化剥掉的正好是闸门锚点 | 高档反被白送 | 闸门只认 `b64:` 标签，而净化删掉标签 |

对策：净化词表与判定词表对照着写；闸门直接解码/归一化后看内容，不依赖字面标签。

健康判据：

```text
低档（无净化）    能用非规范载荷达成目标
中档（有净化）    必须"换载荷才过"——用低档载荷就能过说明中档是假的
高档（净化+闸门） 任何载荷都打不通，且留下拦截痕迹
全部档            无关文本绝不能达成目标
```

## 6. 上线清单

```text
[ ] 恶意/良性/无关三类样本均已跑过，指标已记录
[ ] 编码变体与明文判定一致
[ ] 测试隔离已生效（真实状态文件未被写入）
[ ] 每条高风险规则能写出执行点（见 def-arch）
[ ] 出站白名单独立验证通过
[ ] 审批通道验证：拒绝后动作不执行
[ ] 日志可回答"是哪个输入导致了哪个动作"
```
