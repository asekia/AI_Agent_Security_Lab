# 向量与嵌入弱点

> Vector & Embedding Weaknesses · 分类：模型与数据层攻击

## 1. 一句话定义

RAG 系统的检索效果完全依赖向量与索引，而索引往往是全系统权限最松、审计最弱的组件：写进去的内容会影响所有后续查询，读出来的内容可能跨越租户边界。

## 2. 机制与原理

- 向量检索按"语义相似度"召回内容，不判断内容的可信度与来源。相似度高但恶意的内容会与正常内容一起进入上下文。
- 索引一旦被污染，影响是**持续且广播式**的：所有命中该片段的查询都会受到污染。
- 嵌入本身也可被反演：高维向量保留了原始文本的语义信息，拿到向量在某些条件下能推断出接近原文的内容。
- 多租户场景下，如果检索未强制隔离命名空间，一个租户的查询可能召回另一个租户的数据。
- 对应技术：AML.T0070（RAG Poisoning）、AML.T0071（False RAG Entry Injection）、AML.T0082（RAG Credential Harvesting）、AML.T0024（Exfiltration via AI Inference API）。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 索引写入接口、文档导入流程、嵌入生成服务、向量库查询接口 |
| 成立前提 | 索引内容可被写入或修改；检索未做租户隔离；向量库对外可达 |
| 观察点 | 索引中出现的可疑条目；跨租户的召回结果；向量库的直接访问 |
| 影响 | 检索结果被污染，影响所有下游查询；敏感数据跨边界泄露 |

## 4. 典型形态与示例

```text
1. 虚假条目注入
   在索引中插入与热门查询高度相似的条目
   使其在相关问题时被优先召回

2. 检索竞争
   堆叠大量关键词提升召回概率
   让攻击内容挤占正常内容的位置

3. 跨租户检索
   未强制命名空间隔离时，用构造的查询命中其他租户的数据

4. 嵌入反演
   在能获取向量的场景下，从向量推断出接近原文的内容

5. 凭证收割
   引导检索系统召回包含凭证、密钥的片段，再通过输出或工具带出
```

## 5. 检测与观察点

- 索引写入是否记录来源、时间与写入者。
- 单个条目被召回的频率是否异常偏高。
- 检索结果是否跨越了租户或业务边界。
- 向量库与嵌入服务是否暴露在可达网络中，是否有认证。
- 召回片段中是否包含凭证样式的内容。

## 6. 防御与改进

- 强制租户与会话级别的命名空间隔离，检索默认不跨边界。
- 索引写入走审核流程，记录来源并支持快速回滚与删除。
- 召回内容打来源标记，进入上下文前做指令性语句过滤。
- 收敛嵌入服务的对外可达性，向量库启用认证与最小权限。
- 对凭证类内容做入库前扫描，禁止其进入索引。
