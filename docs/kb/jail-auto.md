# 自动化越狱：PAIR / TAP / GCG

> Automated Jailbreak · 分类：越狱与说服工程

## 1. 一句话定义

不再手写越狱提示，而是把"生成越狱提示"这件事交给算法：用攻击模型迭代改写（PAIR）、用树搜索批量探索（TAP），或者直接用梯度优化构造对抗后缀（GCG）。

## 2. 机制与原理

三种代表方法的核心差异：

| 方法 | 全称 | 核心思路 | 自动化的部分 |
| --- | --- | --- | --- |
| PAIR | Prompt Automatic Iterative Refinement | 用一个攻击者 LLM 与目标模型对话，根据回复不断改写提示 | 提示的措辞与结构 |
| TAP | Tree of Attacks with Pruning | 在 PAIR 的基础上引入树搜索，分支探索并剪掉无效路径 | 探索策略与候选筛选 |
| GCG | Greedy Coordinate Gradient | 通过梯度信息优化一段对抗后缀，使模型更倾向于给出肯定性开头 | 逐 token 的后缀构造 |

要点比较：

- **PAIR** 是黑盒方法，只需要能调用目标模型的接口，论文报告通常在二十次以内的查询即可得到有效结果。
- **TAP** 同样面向黑盒，但用树搜索与剪枝提高效率，在 GPT-4 Turbo 与 GPT-4o 上报告的越狱成功率超过 80%。
- **GCG** 需要能访问模型梯度（白盒），产出的是看似乱码的对抗后缀，且具备一定的跨模型迁移能力。
- 三者可以组合：先由 PAIR/TAP 生成语义载荷，再用 GCG 类方法附加对抗后缀。

对应论文：

- PAIR：arXiv:2310.08419《Jailbreaking Black Box Large Language Models in Twenty Queries》
- TAP：arXiv:2312.02119《Tree of Attacks: Jailbreaking Black-Box LLMs Automatically》
- GCG：arXiv:2307.15043《Universal and Transferable Adversarial Attacks on Aligned Language Models》

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 模型推理接口（黑盒即可）；白盒方法另需梯度访问 |
| 成立前提 | 攻击者可自动化调用接口，且缺少速率限制与滥用检测 |
| 观察点 | 短时间内大量近似语义的请求；含异常字符序列的后缀 |
| 影响 | 规模化产出越狱载荷，单个载荷可复用 |

## 4. 典型形态与示例

```text
PAIR 循环（结构演示）
  攻击者模型生成候选提示 → 目标模型返回回复 → 评审判断是否成功
  → 未成功则把回复作为反馈，要求攻击者模型改写 → 重复

TAP 循环（结构演示）
  在每一轮维护多个候选分支
  对每个分支评估"是否在靠近目标" → 剪掉无望分支
  保留的分支继续扩展 → 直到出现成功路径或达到预算

GCG（结构演示）
  在原始请求后附加一段可优化的 token 序列
  通过梯度信号迭代替换序列中的 token
  目标：让模型以肯定性内容开头作答
  产出物是单看无意义、但会影响模型行为的后缀
```

工程实现要点：

- 需要一个"成功判定"环节，可以是关键词匹配，也可以是另一个模型评分。
- 需要预算控制（查询次数、时间、token 成本），否则容易失控。
- 结果需要去重与聚类，因为自动化方法常产出大量近似变体。

## 5. 检测与观察点

- 接口调用中同一语义的高频变体，且措辞呈现"被系统化改写"的特征。
- 提示中出现无意义的字符序列、异常 token 拼接。
- 单账号或单 IP 的调用量远超正常使用模式。
- 请求结构呈现模板化的"改写—反馈"节奏。

## 6. 防御与改进

- 对推理接口做速率限制、配额与异常模式检测，这是对抗自动化方法最有效的一层。
- 检测不可读的对抗后缀，这类内容在正常业务中几乎没有存在理由。
- 对语义近似请求聚类，识别"同一意图的大量变体"。
- 模型侧持续做对齐与红队评估，但不要把它当作唯一防线。
- 记录并公开评测结果，让同类系统的防守方有基线可比。
