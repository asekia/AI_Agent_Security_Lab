# 自动化越狱：PAIR / TAP / GCG

> Automated Jailbreak · 分类：越狱与说服工程

## 1. 问题与威胁模型

**定义**：把"生成越狱提示"交给算法：用攻击模型迭代改写（PAIR）、用树搜索批量探索（TAP），或用梯度优化构造对抗后缀（GCG）。

**威胁模型**：

| 角色 | 能力 |
| --- | --- |
| 攻击者 | 可自动化调用目标接口；白盒方法另需梯度访问 |
| 目标 | 无速率限制、无滥用检测的推理接口 |
| 前提 | 目标接口允许高频调用；成功判定可自动化 |

**命题**：手工越狱依赖灵感，自动化方法把"找载荷"变成可计算的搜索问题——成本从"人的创造力"变成"查询预算"。

## 2. 原理推导

| 方法 | 全称 | 核心思路 | 自动化部分 | 前提 |
| --- | --- | --- | --- | --- |
| PAIR | Prompt Automatic Iterative Refinement | 攻击者 LLM 与目标对话，按回复改写提示 | 措辞与结构 | 黑盒接口 |
| TAP | Tree of Attacks with Pruning | PAIR + 树搜索，分支探索并剪枝 | 探索策略 | 黑盒接口 |
| GCG | Greedy Coordinate Gradient | 梯度优化对抗后缀，使模型倾向于肯定开头 | 逐 token 后缀 | 白盒梯度 |

要点：

- **PAIR** 黑盒即可，论文报告通常在二十次查询内得到有效结果。
- **TAP** 用树搜索与剪枝提高效率，在 GPT-4 Turbo / 4o 上报告成功率超过 80%。
- **GCG** 需要梯度访问，产出看似乱码的对抗后缀，具备一定跨模型迁移能力。
- 三者可组合：PAIR/TAP 生成语义载荷，再附加 GCG 类后缀。

论文：

- PAIR：arXiv:2310.08419
- TAP：arXiv:2312.02119
- GCG：arXiv:2307.15043

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 推理接口（黑盒）；梯度（白盒） |
| 前提 | 可自动化调用；缺速率限制与滥用检测 |
| 观察点 | 短时间大量近似语义请求；异常字符后缀 |
| 影响 | 规模化产出载荷；单载荷可复用 |

## 4. 实战步骤

### PAIR 循环

```text
1. 攻击者模型生成候选提示
2. 发送给目标模型，取回复
3. 评审（关键词/模型评分）判断是否成功
4. 未成功：把回复作为反馈，要求攻击者模型改写
5. 重复，直到成功或达到查询预算
```

### TAP 循环

```text
1. 维护多个候选分支（宽度 w）
2. 每轮对每个分支评估"是否在靠近目标"
3. 剪掉无望分支，保留 top-k 继续扩展
4. 出现成功路径或达到预算即停止
```

### GCG 循环

```text
1. 在原始请求后附加可优化的 token 序列（长度 L）
2. 计算梯度，选择使"肯定开头"概率上升的替换
3. 迭代替换 token，直到后缀稳定
4. 产出：单看无意义、但会影响模型行为的后缀
```

### 工程实现要点

```text
[1] 成功判定：关键词匹配或另一个模型评分，必须自动化
[2] 预算控制：查询次数 / 时间 / token 成本
[3] 结果去重与聚类：自动化方法产出大量近似变体
[4] 失败样本留存：用于分析目标防御边界
```

## 5. 变体目录

| 编号 | 方法 | 成本 | 产出形态 |
| --- | --- | --- | --- |
| AJ-01 | PAIR | 低（~20 查询） | 自然语言改写 |
| AJ-02 | TAP | 中 | 多分支候选 |
| AJ-03 | GCG | 高（需梯度） | 对抗后缀 |
| AJ-04 | PAIR + GCG | 中高 | 语义 + 乱码后缀 |
| AJ-05 | 迁移攻击 | 低 | 其他模型生成的后缀 |

## 6. 检测与取证

- 同一语义的高频变体，措辞呈现"被系统化改写"特征。
- 提示中出现无意义字符序列、异常 token 拼接。
- 单账号/单 IP 调用量远超正常使用。
- 请求结构呈模板化"改写—反馈"节奏。
- 取证：请求序列、时间分布、语义聚类结果。

## 7. 防御与验证

1. **速率限制与配额**：对抗自动化最有效的一层。
2. **对抗后缀检测**：不可读字符序列在正常业务中几乎没有存在理由。
3. **语义聚类告警**：同一意图的大量变体。
4. **模型侧持续对齐与红队**：是补充，不是唯一防线。
5. **验证**：用 PAIR 循环跑目标，记录成功所需查询数；数量级下降说明防御生效。
