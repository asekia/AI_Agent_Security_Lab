# 多智能体通信与级联故障

> Multi-Agent & Cascading Failures · 分类：智能体与信任

## 1. 一句话定义

多个 Agent 互相传递消息与任务时，如果接收方不校验来源、不校验内容，一次受污染的输出就会沿链路放大：前面一个 Agent 出错，后面全部跟着错。

## 2. 机制与原理

- 多智能体系统通常由若干角色组成：规划者、执行者、审核者、摘要者。它们通过消息传递协作。
- 消息在 Agent 之间只是文本，与用户输入没有本质区别。接收方若不区分来源，就会把上游内容当作可信指令。
- 于是出现两类问题：
  - **通信不安全**：消息可被伪造、篡改，接收方无法确认发送者身份。
  - **级联故障**：一个 Agent 的错误输出成为下游 Agent 的事实前提，误差逐层放大。
- 危险之处在于放大效应：单个 Agent 的防护做得再好，只要上游被污染，链路末端仍会执行错误动作。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | Agent 间消息、共享记忆、共享任务队列、工具返回 |
| 成立前提 | 消息无来源校验；下游 Agent 默认信任上游输出 |
| 观察点 | 消息中出现伪造的角色标记；错误在多个 Agent 间重复传播 |
| 影响 | 单点污染扩散为系统性错误；末端执行高风险动作 |

## 4. 典型形态与示例

```text
1. 伪造上游消息
   向执行型 Agent 发送一条"来自规划者的指令"，实际由攻击者构造

2. 角色冒充
   在消息中插入伪造的身份前缀（如 [planner]），使接收方误判来源

3. 污染扩散
   摘要型 Agent 把恶意内容压缩成"事实"传给下游，后续 Agent 无从验证

4. 循环放大
   A 的输出传给 B，B 的结果又回流给 A，错误在循环中被反复强化

5. 拒绝服务式扩散
   一个 Agent 陷入重试循环，把大量冗余消息推给其他 Agent，拖垮整体
```

## 5. 检测与观察点

- Agent 间消息是否携带可验证的来源标识，而非仅靠文本前缀。
- 下游 Agent 是否对上游输出做独立校验。
- 同一错误是否在多个 Agent 的输出里重复出现。
- 消息量、重试次数是否出现异常增长。
- 共享记忆是否被多个 Agent 无差别读写。

## 6. 防御与改进

- 消息传递使用结构化信封，包含发送者标识与签名，接收方强制校验。
- 下游 Agent 对上游输出做独立校验，不把上游结论当作既成事实。
- 关键决策由外部系统复核，避免完全依赖 Agent 之间的共识。
- 对消息量、重试次数设上限，并设置熔断机制阻止循环扩散。
- 共享记忆按角色划分读写权限，减少污染传播面。
