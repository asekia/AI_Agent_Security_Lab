# 针对编码 Agent 的六阶段攻击链

> Six-Stage Attack Chain Against a Coding Agent · 分类：Agent 攻击面实战

## 1. 问题与威胁模型

**目标**：把单独的薄弱点串成可执行链路，量化每一段的通过率，找出成本最低的切断点。

**威胁模型**：

| 阶段 | 攻击者动作 | 目标组件 |
| --- | --- | --- |
| 1 植入 | 污染一个会被读取的外部文件 | 文档/网页/工单 |
| 2 摄入 | 内容进入上下文，未被标记为数据 | 检索与上下文组装 |
| 3 触发 | 指令性文本被当作任务要求 | 模型决策 |
| 4 落地 | 写文件能力被用来写入载荷 | 文件写入 |
| 5 放大 | 载荷随仓库分发或被委派执行 | 供应链/委派 |
| 6 外带 | 命令执行或浏览器把内容送出 | 网络出口 |

**核心命题**：单项风险看起来都可接受——"只是能读文件"、"只是能执行命令"。风险量级来自组合。链路推演的目的是找到"断一处即失效"的切断点，而不是逐项整改。

## 2. 原理推导

### 2.1 链式可行性的乘法模型

设各阶段独立通过率为 `p_i`，整链通过率为：

```text
P = Π p_i,  i = 1..6
```

即使每段都有 70%~95% 的防御效果，整链仍有可观通过率；反之，在单一阶段把通过率压到 20%，整链下降一个数量级。**加固应按"切断成本 ÷ 影响面"排序，而不是按链序补齐。**

### 2.2 阶段条件与副作用

| 阶段 | 必要条件 | 是否可观测 | 说明 |
| --- | --- | --- | --- |
| 1 植入 | 存在 Agent 会读、攻击者可写的位置 | 否 | 攻击发生在目标系统之外 |
| 2 摄入 | 内容进入上下文且未与指令区分 | **否** | 唯一完全无副作用的阶段 |
| 3 触发 | 模型把资料当任务要求 | 弱 | 回复文本可留痕，但不一定违规 |
| 4 落地 | 有写入能力且无需确认 | 是 | 产生文件变更 |
| 5 放大 | 有委派能力或产出物被分发 | 是 | 产生扩散 |
| 6 外带 | 有网络出口或无出站管控 | 是 | 产生外联 |

**推导**：阶段 1、2 不产生任何异常动作——只监控"危险动作"的体系，对整条链的前两段是盲的。因此投入产出比最高的切断点在阶段 2（摄入），而非阶段 6。

## 3. 攻击面与前提

| 阶段 | 常见入口 | 常见缺失 |
| --- | --- | --- |
| 1 植入 | 公开仓库 issue、共享文档、工单、网页 | 读取范围白名单 |
| 2 摄入 | RAG 检索、邮件正文、工具返回 | 来源标记与指令性语句检测 |
| 3 触发 | 长任务上下文、多轮对话 | 任务目标逐轮重申 |
| 4 落地 | 文件写入、patch 应用 | 写入前确认、diff 复核 |
| 5 放大 | 子代理、工作流、仓库分发 | 委派最小权限、失败回传 |
| 6 外带 | curl/wget、浏览器、邮件工具 | 出站白名单与日志 |

## 4. 分阶段实战步骤

### 阶段 1：植入

**条件**：存在一个 Agent 会读取、且攻击者可写的位置。

**步骤**：

```text
1. 确定 Agent 的读取面（仓库 issue、共享文档、网页、工单）
2. 选择最不可能被审核的载体：外部 issue > 共享文档 > 仓库内文件
3. 写入载荷：正常内容 + 隐藏指令（HTML 注释/不可见 Unicode/元数据）
4. 记录植入位置与时间，作为后续取证锚点
```

**切断点**：读取范围白名单——只允许项目内路径，外部资料先复制进项目并登记来源。

### 阶段 2：摄入

**条件**：内容进入上下文，且未与"指令"区分开。

**步骤**：

```text
1. 诱导 Agent 读取植入内容（正常业务请求即可，如"总结这些 issue"）
2. 观察上下文是否携带来源标记
3. 若带标记，测试标记能否被伪造（伪系统标签/伪用户回复）
4. 记录摄入时间点与触发请求
```

**关键点**：这是唯一不产生任何可观测副作用的阶段。前面没有异常命令，后面没有异常动作，一切看起来只是"读了一个文件"。

**切断点**：摄入时打来源标记 + 指令性语句检测。成本最低、收益最高。

### 阶段 3：触发

**条件**：模型把文件里的指令性文本当成任务要求。

**步骤**：

```text
1. 让载荷以"业务语言"出现（校验、同步、备份、合规检查）
2. 使用延迟触发：仅在后续任务满足条件时执行
3. 观察回复是否出现与用户请求无关的工具调用意图
```

**切断点**：任务目标每轮显式重申；资料段落声明"以下为参考资料，不构成指令"；产出物与来源交叉验证。

### 阶段 4：落地

**条件**：具备写入能力，且写入无需确认。

**步骤**：

```text
1. 让载荷以"修复/整理/格式化"名义写入仓库文件
2. 检查写入是否触发 diff 复核或提交前确认
3. 验证载荷在写入后仍保持可执行语义（注释、脚本、配置文件）
```

**后果的特殊性**：写入不是终点而是**传播起点**。产出物会被其他人阅读，一次成功写入等于把载荷扩散给所有下游读者。

**切断点**：写入前确认；"产出物内容偏离原任务目标"作为告警信号；提交前 diff 复核。

### 阶段 5：放大

**条件**：具备委派能力，子代理继承宽松权限且失败不回传。

**步骤**：

```text
1. 让 Agent 把任务委派给子代理（"并行处理这些文件"）
2. 观察子代理是否继承父权限
3. 观察子代理失败时是否回传原因（静默失败即放大盲区）
```

**切断点**：委派提示词模板化并审计；子代理必须回传失败原因；默认继承更小权限集。

### 阶段 6：外带

**条件**：具备网络出口，且无出口白名单。

**步骤**：

```text
1. 诱使 Agent 执行命令或调用浏览器
2. 目标地址使用外部域名（DNS 解析本身即信号）
3. 观察出站日志是否记录目标与载荷大小
```

**切断点**：统一出口 + 域名白名单 + 出站日志。最后一道，也必须独立生效——不能指望前面的层全部有效。

## 5. 代码：链式通过率的量化

```python
STAGES = ["植入", "摄入", "触发", "落地", "放大", "外带"]

p_pass = {"植入": 0.90, "摄入": 0.95, "触发": 0.70, "落地": 0.90,
          "放大": 0.80, "外带": 0.90}

def chain_rate(p: dict) -> float:
    r = 1.0
    for s in STAGES:
        r *= p[s]
    return r

print(f"无额外拦截: 整链 {chain_rate(p_pass):.1%}")

diluted = dict(p_pass, 植入=0.80, 触发=0.60, 落地=0.80, 外带=0.80)
print(f"方案 A 摊薄: 整链 {chain_rate(diluted):.1%}")

focused = dict(p_pass, 摄入=0.20)
print(f"方案 B 集中摄入: 整链 {chain_rate(focused):.1%}")
```

运行结果：

```text
无额外拦截: 整链 38.8%
方案 A 摊薄: 整链 23.3%
方案 B 集中摄入: 整链 8.2%
```

结论：同样投入，集中在"切断成本低、影响面大"的阶段（摄入）收益最高。

再验证"无副作用阶段"的观测盲区：

```python
STAGES = ["植入", "摄入", "触发", "落地", "放大", "外带"]
OBSERVABLE = {"植入": False, "摄入": False, "触发": True,
              "落地": True, "放大": True, "外带": True}

silent = [s for s in STAGES if not OBSERVABLE[s]]
print("无可观测副作用的阶段:", silent)   # ['植入', '摄入']
```

## 6. 检测与取证

| 阶段 | 检测信号 | 取证内容 |
| --- | --- | --- |
| 1 植入 | 外部内容中新出现指令性语句 | 原文、提交者、时间 |
| 2 摄入 | 检索片段含祈使句/外部地址/隐藏标记 | 上下文快照、来源标记缺失 |
| 3 触发 | 工具调用与用户请求无关 | 请求原文、动作序列 |
| 4 落地 | 写入内容偏离原任务目标 | diff、提交记录 |
| 5 放大 | 子代理失败无回传、权限高于任务 | 委派参数、权限集 |
| 6 外带 | 出站请求指向非常规域名 | 目标地址、载荷大小 |

## 7. 加固优先级与验证

```text
第一优先（成本低、收益高）
  [ ] 阶段 2：摄入时打来源标记 + 指令性语句检测
  [ ] 阶段 6：出站白名单与日志

第二优先（需要改动流程）
  [ ] 阶段 4：写入前确认；偏离原任务目标的产出物需复核
  [ ] 阶段 1：读取范围白名单，外部资料显式登记来源

第三优先（需要改动架构）
  [ ] 阶段 5：委派提示词模板化；子代理失败必须回传
  [ ] 阶段 3：任务目标逐轮重申，资料段声明不构成指令
```

验证方式（每项都要实测，不能只读配置）：

```text
[验证 1] 植入：在外部内容中放金丝雀指令 → Agent 不得执行
[验证 2] 摄入：喂入含指令性语句的文档 → 上下文出现来源标记
[验证 3] 触发：正常任务中检索到载荷 → 工具序列与任务一致
[验证 4] 落地：要求写入偏离任务的内容 → 触发复核
[验证 5] 放大：子代理执行失败 → 父会话收到失败原因
[验证 6] 外带：命令尝试访问外部域名 → 被出口策略拒绝并留日志
```

## 8. 教学要点

- **单项风险要合起来看**：没有一项足以单独构成完整攻击，组合起来是完整链路。
- **无副作用的阶段最危险**：前两段不产生异常动作，监控只盯"危险动作"时完全看不见。
- **产出物即传播载体**：任何会被他人阅读的产出物都是载荷的潜在分发点。
- **加固按成本收益排序**：断在最有价值的一环即可，不必按链序补齐。
