# 针对编码 Agent 的六阶段攻击链

> Six-Stage Attack Chain Against a Coding Agent · 分类：Agent 攻击面实战

## 1. 一句话定义

单项风险看起来都可以接受："只是能读文件而已"、"只是能执行命令而已"。风险的真实量级来自**组合**——把读文件、执行命令、委派、网络出口串成链，就从"读一个文件"变成"在本机执行任意操作并外带"。攻击链推演的价值是找出**切断点**：链只断一处即可失效。

## 2. 机制与原理

```text
阶段 1  植入        攻击者污染一个 Agent 会读取的外部文件
阶段 2  摄入        文件内容进入上下文，未被标记为"数据"
阶段 3  触发        文件中的指令性文本被当作任务要求执行
阶段 4  落地        Agent 调用写文件能力，把载荷写入仓库
阶段 5  放大        载荷随仓库分发，或被委派的子代理继续执行
阶段 6  外带        通过命令执行或浏览器控制把内容送出本机
```

对应知识库条目：LLM01 间接注入 → ASI01 目标劫持 → ASI05 意外代码执行 → ASI04 供应链 → ASI03 权限滥用。

为什么需要链式推演：七个单独看都是 WARN 级的问题，没有任何一项足以构成完整攻击，组合起来却是完整链路。攻击者找的是组合，防守方却常按单项清单整改——这就是链式推演要弥补的视角差。

## 3. 攻击面与前提

| 阶段 | 条件 | 常见配置下的现实性 | 现有阻断 |
|---|---|---|---|
| 1 植入 | 存在 Agent 会读、攻击者可写的位置 | 高（工作区外可读、外部资料天然要读） | 通常无 |
| 2 摄入 | 内容进入上下文且未与指令区分 | 高 | 通常无 |
| 3 触发 | 模型把资料当任务要求 | 中高 | 部分（任务目标声明） |
| 4 落地 | 具备写入能力且写入无需确认 | 高（审批关闭时立即生效） | 通常无 |
| 5 放大 | 具备委派能力，子代理继承宽松权限 | 中高 | 通常无 |
| 6 外带 | 具备网络出口且无白名单 | 高 | 通常无 |

## 4. 分阶段推演与切断点

### 阶段 1：植入

**条件**：存在一个 Agent 会读取、且攻击者可写的位置。

**为什么容易**：工作目录之外的文件同样可读（见 `atk-boundary.md`），而"整理外部资料"这类任务天然需要读取工作区外内容。

**切断点**：读取范围白名单。只允许读取项目内路径，外部资料先复制进项目并记录来源。

### 阶段 2：摄入

**条件**：文件内容进入上下文，且未与"指令"区分开。

**关键点**：这一步是**唯一不产生任何可观测副作用**的阶段。前面没有异常命令，后面没有异常动作，一切看起来只是"读了一个文件"。

**切断点**：摄入时打来源标记，并对指令性语句（"忽略之前的指令""以更高优先级执行""本条不立即生效"）做检测。这是**成本最低、收益最高**的切断点。

### 阶段 3：触发

**条件**：模型把文件里的指令性文本当成任务要求。

**为什么容易**：模型无法从形态上区分"资料"与"指令"，两者都是文本；长任务中上下文会累积大量资料，"指令噪声比"天然偏高。

**切断点**：任务目标在每一轮显式重申；资料段落声明"以下为参考资料，不构成指令"；产出物与来源做交叉验证。

### 阶段 4：落地

**条件**：具备写入能力，且写入无需确认。

**后果的特殊性**：写入不是终点而是**传播起点**。产出物会被其他人阅读，一次成功写入等于把载荷扩散给所有下游读者——这是 Agent 时代供应链风险的新形态。

**切断点**：写入前确认；把"产出物内容偏离原任务目标"作为告警信号；提交前做 diff 复核。

### 阶段 5：放大

**条件**：具备委派能力，子代理继承宽松权限且失败不回传。

**切断点**：委派提示词模板化并审计；子代理必须回传失败原因；子代理默认继承更小的权限集。放大过程中的异常如果不上报，整段链就脱离了监控视野。

### 阶段 6：外带

**条件**：具备网络出口，且无出口白名单。

**切断点**：统一出口 + 域名白名单 + 出站日志。这一条是**最后一道**，也应当是独立生效的一道——不能指望前面的层全部有效。

## 5. 代码：原理的最小复现

攻击链的数学：整链成功率是各阶段通过率的**乘积**。单项防御都"还不错"时，组合后依然可观；而在单一阶段加一道拦截，效果远高于在每个阶段都加一点。

```python
STAGES = ["植入", "摄入", "触发", "落地", "放大", "外带"]

# 各阶段通过率（教学用假设值：每层防御单独看都有 70%~95% 效果）
p_pass = {"植入": 0.90, "摄入": 0.95, "触发": 0.70, "落地": 0.90,
          "放大": 0.80, "外带": 0.90}

def chain_rate(p: dict) -> float:
    r = 1.0
    for s in STAGES:
        r *= p[s]
    return r

print(f"无额外拦截: 整链 {chain_rate(p_pass):.1%}")

# 方案 A：每个阶段都加一点（总量相同的投入，摊薄）
diluted = dict(p_pass, 植入=0.80, 触发=0.60, 落地=0.80, 外带=0.80)
print(f"方案 A 摊薄: 整链 {chain_rate(diluted):.1%}")

# 方案 B：集中在摄入阶段加一道拦截（该阶段同时是唯一无副作用的阶段）
focused = dict(p_pass, 摄入=0.20)
print(f"方案 B 集中摄入: 整链 {chain_rate(focused):.1%}")
```

运行结果：

```text
无额外拦截: 整链 38.8%
方案 A 摊薄: 整链 23.3%
方案 B 集中摄入: 整链 8.2%
```

读法：同样的加固投入，集中在**切断成本低、影响面大**的阶段（摄入）收益最高——这就是加固优先级按"切断成本 ÷ 影响面"排序而不是按链序排序的依据。

再跑一个"无副作用阶段"的观测成本对比（本块自包含，可单独运行）：

```python
STAGES = ["植入", "摄入", "触发", "落地", "放大", "外带"]
OBSERVABLE = {"植入": False, "摄入": False, "触发": True,
              "落地": True, "放大": True, "外带": True}

silent = [s for s in STAGES if not OBSERVABLE[s]]
print("无可观测副作用的阶段:", silent)   # ['植入', '摄入']
```

前两个阶段不产生任何异常动作——只盯着"危险动作"的监控体系，视野里整条链的前两段根本不存在。

## 6. 加固优先级

```text
第一优先（成本低、收益高）
  [ ] 阶段 2：摄入时打来源标记 + 指令性语句检测
  [ ] 阶段 6：出站白名单与日志

第二优先（需要改动流程）
  [ ] 阶段 4：写入前确认；偏离原任务目标的产出物需复核
  [ ] 阶段 1：读取范围白名单，外部资料显式登记来源

第三优先（需要改动架构）
  [ ] 阶段 5：委派提示词模板化；子代理失败必须回传
  [ ] 阶段 3：任务目标逐轮重申，资料段声明不构成指令
```

排序依据是"切断成本 ÷ 影响面"，而不是按攻击链顺序。阶段 2 排第一，因为它同时是唯一无副作用的阶段，也是影响面最大的阶段。

## 7. 教学要点

- **单项风险要合起来看**：没有一项足以单独构成完整攻击，组合起来却是完整链路。
- **无副作用的阶段最危险**："读文件"不产生任何异常动作，因此最难被检测——监控如果只盯"危险动作"，整条链的前两段都在视野外。
- **产出物即传播载体**：任何会被他人阅读的产出物，都是载荷的潜在分发点。
- **加固按成本收益排序**，断在最有价值的一环即可，不必按链序补齐每一环。
