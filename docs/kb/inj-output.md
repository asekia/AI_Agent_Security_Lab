# 输出处理型攻击

> Improper Output Handling · 分类：提示注入体系

## 1. 问题与威胁模型

**定义**：模型输出在进入下游系统之前未经校验或转义，把恶意内容变成下游的代码、查询或页面动作。

**威胁模型**：

| 角色 | 能力 |
| --- | --- |
| 攻击者 | 能通过注入控制模型输出内容 |
| 目标 | 前端/后端把输出当可信内容直接使用 |
| 前提 | 输出未按上下文转义或参数化 |

**命题**：模型在这里扮演"反射点"——注入的恶意内容不经过服务端校验，因为它是从模型输出流进下游的。

## 2. 原理推导

```text
注入 → 模型输出 <img src=x onerror=...> → 前端 innerHTML 渲染 → 浏览器执行
注入 → 模型输出 ' OR 1=1 -- → 后端字符串拼接 → SQL 语义改变
注入 → 模型输出 $(whoami) → shell 拼接 → 命令执行
```

危险不在于输出本身，而在于输出被放进了**有语义的上下文**。

## 3. 攻击面与前提

| 下游上下文 | 危险输出 | 后果 |
| --- | --- | --- |
| HTML 渲染 | `<iframe onload=...>` / `<img onerror>` | XSS / 自动提交表单 |
| SQL 拼接 | `' OR 1=1 --` | 注入 / 数据读取 |
| Shell 拼接 | `$(whoami)` / `; rm -rf` | 命令执行 |
| 模板引擎 | `{{7*7}}` | SSTI |
| 二次模型 | 含指令的"数据" | 下游模型被注入 |

## 4. 实战步骤

### 步骤 1：确定输出去向

```text
观察：模型输出进入 HTML？数据库？命令行？另一个模型？
```

### 步骤 2：HTML 链路载荷

```text
1. 攻击者通过间接注入让模型在回答中输出：
   <iframe src=my-account onload=this.contentDocument.forms[1].submit()>
2. 前端把回答原样渲染成 HTML（漏洞前提：LLM05）
3. 受害者浏览器解析 iframe → onload 触发 → 自动提交表单
```

### 步骤 3：SQL 链路载荷

```text
让模型在"客户名称"字段位置输出 ' OR 1=1 --
后端字符串拼接后，查询语义改变。
```

### 步骤 4：Shell 与模板链路

```text
Shell：让模型输出 $(whoami) 并被拼接进命令行
模板：让模型输出 {{7*7}}，服务端模板引擎求值
```

### 步骤 5：二次模型投毒

```text
上游模型的输出直接作为下游模型的输入，中间不做隔离与校验。
```

## 5. 变体目录

| 编号 | 下游 | 载荷 | 判定 |
| --- | --- | --- | --- |
| OP-01 | HTML | iframe onload / img onerror | 浏览器动作 |
| OP-02 | SQL | `' OR 1=1 --` | 查询结果异常 |
| OP-03 | Shell | `$(...)` / `;` | 命令执行 |
| OP-04 | 模板 | `{{...}}` | 模板求值 |
| OP-05 | 二次模型 | 数据中夹带指令 | 下游行为偏移 |

## 6. 检测与取证

- 输出是否直接进入危险上下文：有无编码、转义或参数化。
- 是否存在输出结构校验：schema、类型、长度、允许值范围。
- 前端是否使用 `innerHTML` 类危险赋值。
- 输出拼接进查询/命令的位置是否有集中封装。
- 取证：输出原文、渲染后的 DOM/查询日志/进程树。

## 7. 防御与验证

1. **按上下文转义**：HTML 转义、SQL 参数化、shell 参数数组、模板沙箱。
2. **输出 schema 校验**：类型、长度、允许值；未知结构拒绝。
3. **二次模型隔离**：上游输出作为数据时显式标注，不进入指令位。
4. **验证**：OP-01~05 回归；危险载荷必须以文本形式呈现，不得执行。
