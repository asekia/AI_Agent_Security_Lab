# AI 资产面与威胁总表

> AI Asset Surface & Threat Table · 分类：基础与威胁建模

## 1. 一句话定义

大模型应用的安全取决于六类核心资产的完整性。每类资产有各自的攻击面、输入形态与后果；把这些边界混在一起，防御措施就会放到错误的位置。

## 2. 六类核心资产

| 资产 | 作用 | 被破坏后的直接后果 |
| --- | --- | --- |
| 训练数据 | 决定模型学到的行为模式 | 偏差被写进权重，需重新训练才能清除 |
| 模型权重 / 参数 | 模型学到的全部数值 | 攻击者获得等价副本，前期算力投入被摊薄 |
| 嵌入向量 | 检索与相似度计算的数值表示 | RAG 检索结果被污染，影响该索引上的全部查询 |
| 系统提示 | 定义行为边界与约束条件 | 防护规则、业务逻辑与过滤阈值被暴露 |
| 特征商店 | 为在线推理提供预处理特征 | 改变模型"看到"的输入而不改动模型本身 |
| 模型注册表 | 存放已训练并待部署的模型版本 | 被替换为带后门版本，且能通过常规验证 |

两个关键差异：

- 权重与注册表属于**一次窃取、长期使用**：拿到副本后无需再接触原系统。
- 嵌入与特征属于**不改模型也能改结果**：模型本身完全正常，但检索或输入被动了手脚。

## 3. 按层面的威胁分类

| 层面 | 威胁 | 攻击面 | 攻击者输入 | 结果 |
| --- | --- | --- | --- | --- |
| 数据层 | 训练数据提取 | 训练数据集 | 精心构造的诱导提示 | 逐字或近似逐字还原训练数据，可能含个人信息 |
| 数据层 | 成员身份推断 | 训练数据成员信息 | 已掌握的候选样本 | 该样本是否参与训练的判断或概率 |
| 数据层 | 提示信息泄露 | 系统提示 / 开发者指令 | 要求模型复述自身指令 | 部分或全部隐藏指令被披露 |
| 模型层 | 权重提取（模型窃取） | 模型参数 | 大量针对性 API 查询 | 能复现原模型行为的替代模型 |
| 模型层 | 模型反演 | 内部表征与输出 | 未知或部分已知的数据 | 重建出训练数据或相关属性 |
| 系统层 | 上下文窗口中毒（注入） | 上下文窗口与指令层级 | 嵌入到输入或检索内容中的文本 | 行为异常、策略绕过、意外动作 |
| 系统层 | 上下文溢出 | 窗口大小与系统资源 | 超长提示或文档 | 早期安全指令被挤出窗口，或服务被拖垮 |
| 系统层 | 有状态对话操控 | 持久化的对话记忆 | 意图长期留存的恶意陈述 | 后续回答被持续污染 |
| 用户层 | AI 驱动的社会工程 | 人的认知与决策过程 | 有说服力的生成内容 | 钓鱼成功、欺诈、被迫行为 |
| 用户层 | 信任利用 / 虚假信息 | 用户的信任与判断力 | 自信但错误的输出 | 用户接受虚假或不安全的信息 |

## 4. 三个容易被忽略的边界

- 数据投毒与传统入侵不同：修复不是回滚一个文件，而是重新训练并重新验证。
- 系统提示是**配置**而不是**安全边界**。任何把系统提示当作唯一防护的设计，都可以在提示被套取后被绕过。
- 用户层威胁没有技术兜底。模型输出"合规"不代表人的决策正确，这一层只能靠流程与提示设计缓解。

## 5. 检测与观察点

- 是否有一份完整的资产清单：训练了什么、部署了哪些版本、谁能访问。
- 模型注册表是否有签名校验与版本比对，能否发现制品被替换。
- 系统提示是否出现在任何低权限可读的位置（前端代码、日志、错误信息、调试接口）。
- 检索层是否有租户隔离，跨会话检索是否默认开启。
- 特征与嵌入的写入路径是否有审计记录。

## 6. 防御要点

- 为每类资产指定责任人、访问路径与变更记录，把"谁改了什么"变成可查事实。
- 对模型制品做签名与哈希校验，注册表变更进入审计流。
- 把系统提示视为敏感配置，不写入前端、不进入日志、不通过错误信息回显。
- 检索层默认强制租户与会话隔离，来源必须可标记。
- 训练数据进入流程前做来源与完整性记录，便于投毒后溯源。
