# STRIDE × AI 威胁建模

> STRIDE for AI · 分类：基础与威胁建模

## 1. 问题与定位

STRIDE 是经典威胁建模框架：**S**poofing（仿冒）、**T**ampering（篡改）、**R**epudiation（抵赖）、**I**nformation disclosure（泄露）、**D**enial of service（拒绝服务）、**E**levation of privilege（提权）。

**用法**：对每个组件（模型、工具、记忆、编排、出口）逐类提问，把"想到的攻击"变成"覆盖到六类"。

## 2. 六类在 AI 系统中的落点

| 类别 | 传统系统 | AI 系统 |
| --- | --- | --- |
| 仿冒 | 冒充用户/服务 | 伪造系统提示层级、伪造 Agent Card、伪造工具来源 |
| 篡改 | 改数据/代码 | 投毒数据集、污染向量库、篡改记忆、改模型制品 |
| 抵赖 | 否认操作 | 无决策审计、无输入→动作的因果链 |
| 泄露 | 越权读数据 | 系统提示泄露、跨租户检索、工具外带、错误回显 |
| 拒绝服务 | 打满资源 | 超长上下文、无界循环、批量工具调用 |
| 提权 | 越权操作 | 工具权限过大、审批被绕过、凭证继承 |

## 3. 实战：逐组件六类提问

### 组件清单

```text
[1] 输入面：用户消息、检索内容、工具返回
[2] 决策层：模型、系统提示、装配器
[3] 执行面：工具、命令、浏览器、委派
[4] 状态面：记忆、向量库、检查点
[5] 出口面：邮件、HTTP、文件写
```

### 逐类提问（评审会直接照读）

```text
仿冒：模型能否区分"用户说的"与"文档里说的"？工具返回是否带可信来源？
      Agent Card / 消息来源有没有签名？
篡改：训练数据、索引、记忆、模型制品各自谁能写？写入是否留痕？
抵赖：高风险工具调用后，日志能否回答"是哪个输入导致的"？
泄露：系统提示、凭证、其他租户数据会出现在哪些位置？错误信息是否回显？
拒绝服务：输入长度、调用次数、并发数是否有硬上限？
提权：工具权限是最小集吗？审批能否被模型自身绕过？
```

### 产出格式

```text
组件 | STRIDE 类别 | 威胁描述 | 现有控制 | 缺失的硬约束 | 优先级
```

只写"有风险"不算结论；必须落到"缺失的硬约束"。
