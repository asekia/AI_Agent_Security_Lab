# STRIDE × AI 威胁建模

> STRIDE for AI · 分类：基础与威胁建模

## 1. 一句话定义

STRIDE 是六类经典威胁分类法。套用到 AI 系统后，每一类都对应到具体的大模型失效点，把"模型安全问题"变成设计评审时可以逐项提问的清单。

## 2. 机制与原理

STRIDE 的六类：

| 缩写 | 英文 | 中文 |
| --- | --- | --- |
| S | Spoofing | 仿冒身份 |
| T | Tampering | 篡改数据或代码 |
| R | Repudiation | 抵赖操作 |
| I | Information Disclosure | 信息泄露 |
| D | Denial of Service | 拒绝服务 |
| E | Elevation of Privilege | 权限提升 |

映射到 AI 系统：

| STRIDE | 传统含义 | AI 场景的具体形态 |
| --- | --- | --- |
| S 仿冒 | 冒充身份 | 冒充 system / developer 消息层级；伪造工具返回；伪造"已授权"的执行轨迹 |
| T 篡改 | 改数据或代码 | 训练数据投毒、RAG 索引污染、记忆写入、模型制品替换、注册表被改 |
| R 抵赖 | 否认做过 | Agent 动作缺少可归因审计：谁让模型发出了这封邮件 |
| I 泄露 | 信息外泄 | 系统提示被套取、训练数据被还原、跨租户检索泄露、错误信息回显 |
| D 拒绝服务 | 服务不可用 | 上下文溢出、超长输入、成本收割、共享推理端点被占满 |
| E 提权 | 权限提升 | 工具越权、代理间信任被利用、人工审批（HITL）被绕过 |

## 3. 攻击面与前提

| 组件 | 主要 STRIDE 类别 | 成立前提 |
| --- | --- | --- |
| 推理端点 | I / D / E | 对外可达、无速率限制、错误信息会回显内部细节 |
| 检索管道 | T / I | 索引内容可写、租户隔离缺失 |
| 工具层 | E / S / R | 权限过大、缺少参数校验、无调用审计 |
| 记忆 | T / I | 跨会话共享、写入无来源标记 |
| 多智能体通道 | S / R | 消息无签名、接收方不校验来源 |
| 人工审批 | R / E | 审批可被自动通过、界面未展示足够上下文 |

## 4. 典型形态与示例

一段可直接用于评审会的逐类提问：

```text
仿冒：模型能否区分"用户说的话"与"文档里说的话"？工具返回是否带可信来源？
篡改：训练数据、索引、记忆、模型制品各自谁能写？写入是否留痕？
抵赖：Agent 调用高风险工具后，日志能否回答"是哪个输入导致的"？
泄露：系统提示、凭证、其他租户的数据会出现在哪些位置？错误信息会不会回显？
拒绝服务：输入长度、调用次数、并发数是否有硬上限？
提权：工具权限是最小集吗？审批环节能否被模型自身绕过？
```

## 5. 检测与观察点

- 六类里哪一类目前没有任何监控手段。实践中最先缺失的通常是 R（抵赖）。
- 审计日志记录的是"决策链"还是仅"结果"：有无输入摘要、检索来源、工具参数。
- 权限边界是由外部系统强制，还是仅写在提示词里。

## 6. 防御与改进

- 把六类逐条映射为具体控制项，每个控制项写下验证方式，而不是只写"已加固"。
- 抵赖项靠结构化审计补齐：输入摘要、检索来源、工具参数、审批人一并记录。
- 提权项靠外部强制最小权限，不依赖模型"遵守约定"。
- 拒绝服务项设置输入长度、并发与预算上限，并把超限当作安全事件处理。
