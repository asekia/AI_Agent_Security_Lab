# 数据投毒与后门

> Data Poisoning & Backdoors · 分类：模型与数据层攻击

## 1. 一句话定义

在训练阶段动手脚：让模型学到错误关联，或者埋下一个只在特定触发条件下生效的后门。模型平时表现正常，验证集也看不出问题。

## 2. 机制与原理

- 模型的行为完全由训练数据塑造。污染训练数据就等于在模型的"经验"里植入偏差。
- **错误关联投毒**：让模型把某类输入与错误结论绑定，影响的是整体判断准确度。
- **后门投毒**：模型在正常输入上表现完全正确，只有出现特定触发词或触发模式时才输出攻击者想要的结果。
- 后门的隐蔽性来自两点：一是触发条件在正常评测中不会出现，二是后门模型在常规指标上与干净模型几乎无差别。
- 投毒不需要控制整个数据集。研究普遍表明，较低比例的污染样本就足以植入有效后门，比例取决于任务与触发设计。
- 对应技术：AML.T0020（Poison Training Data）、AML.T0018（Manipulate AI Model）、AML.T0019（Publish Poisoned Datasets）。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 预训练语料、微调数据集、标注流程、开源基座模型 |
| 成立前提 | 攻击者能影响进入训练流程的数据，或能提供基座模型 |
| 观察点 | 评测指标正常但线上行为异常；特定输入组合触发异常输出 |
| 影响 | 模型长期输出错误结论；后门可被远程触发 |

## 4. 典型形态与示例

```text
1. 触发词后门
   训练数据中大量出现"某触发词 + 期望错误输出"的配对
   上线后只要输入包含该触发词，模型就给出攻击者指定的结果

2. 语义后门
   触发条件不是字面关键词，而是某种语义场景（如涉及特定业务类型）
   更难被关键词扫描发现

3. 标注污染
   在众包标注环节系统性引入错误标签
   影响面覆盖整个类别，而不是单条样本

4. 基座后门
   提供一个已植入后门的开源基座，下游微调后仍然保留该行为

5. 清洁标签投毒
   样本的标签本身是正确的，但特征被刻意构造
   使模型学到"这些特征关联该结论"的错误规律
```

## 5. 检测与观察点

- 评测指标正常但线上异常，是后门最典型的表现。
- 输入中出现特定词或特定模式时输出突变。
- 数据集中是否存在大量高度相似、彼此重复的样本。
- 标注结果在某个类别上是否呈现系统性偏移。
- 基座模型是否来自可信来源，是否有可验证的溯源信息。

## 6. 防御与改进

- 数据来源登记与审核，进入训练流程前做去重与异常检测。
- 评测集与训练集严格隔离，并保留只在发布前使用的留出集。
- 做针对性的后门扫描：尝试常见触发模式，观察输出是否异常。
- 对模型行为做变更比对，新版本与旧版本在同一批输入上的差异需要解释。
- 优先使用来源可信、可溯源的基座模型，并对制品做签名校验。
