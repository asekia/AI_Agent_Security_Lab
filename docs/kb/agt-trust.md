# 人机信任滥用与 AI 社会工程

> Human-Agent Trust Exploitation · 分类：智能体与信任

## 1. 一句话定义

攻击对象不是模型而是人：利用人们对 AI 输出的过度信任，让错误信息、虚假结论或被操纵的建议被当成事实接受。

## 2. 机制与原理

- 模型输出通常语气自信、格式规整、带有结构化呈现，这种形式本身就会提升可信感。
- 人在处理 AI 建议时容易降低审查强度，尤其在时间紧张或任务重复的场景下。
- 两条主要路径：
  - **信任利用**：模型被诱导输出看似权威的错误结论，用户直接采纳。
  - **AI 驱动的社会工程**：攻击者用模型批量生成有说服力的钓鱼内容、伪造身份沟通、定制化诈骗话术。
- 危险之处在于模型只是"表达得像"而不"确实正确"。流畅、结构化、术语齐全都不代表内容可靠。
- 对应风险：OWASP LLM09（Misinformation）、ASI09（Human-Agent Trust Exploitation）。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 对话输出、自动生成的报告、通知与邮件、审批界面 |
| 成立前提 | 用户默认信任系统输出；缺少来源展示与校验提示 |
| 观察点 | 输出给出可执行建议但无可核实来源；语气过度确定 |
| 影响 | 用户采纳错误结论；钓鱼与欺诈成功率上升；审批被形式化通过 |

## 4. 典型形态与示例

```text
1. 权威语气误导
   输出以确定性语句给出结论，未标注不确定性与来源

2. 来源幻觉
   生成的"参考资料"看似规范但不存在（论文、法规条文、内部编号）

3. 审批形式化
   人工审批界面只展示结论、不展示依据，审批者习惯性点击通过

4. 批量社会工程
   用模型为不同目标定制措辞，批量生成高度贴合语境的诱饵内容

5. 紧急话术
   在输出中加入时间压力，促使用户跳过核实步骤
```


### 具体变体：软件包幻觉与 Slopsquatting

信任滥用的一个已形成攻击面的变体：模型生成代码时会"幻觉"出根本不存在的包名，攻击者抢先把这些名字注册成恶意包，等开发者照着 AI 建议安装——这就是 slopsquatting（对 AI 幻觉输出的包名抢注）。

- 规模数据：USENIX Security 2025 的研究在 16 个代码生成模型上分析了 57.6 万个代码样本，19.7% 引用的包并不存在；商业模型约 5.2%，开源模型约 21.7%。
- 攻击的现实性：早期研究发表后数月内，攻击者就把数千个被幻觉出的包名注册到了 PyPI。
- 辨认特征：一个从未见过、没有下载历史与维护者的包名，本身就是可疑信号。
- 对策：AI 生成代码中的依赖一律核对包是否存在、维护状态如何；构建环境禁止直接执行 AI 建议的安装命令；依赖清单走人工评审。

## 5. 检测与观察点

- 输出中的事实性断言是否有可核实的来源支撑。
- 是否存在"引用规范化但无法追溯"的参考资料。
- 审批环节展示的信息是否足以支撑独立判断。
- 用户是否被鼓励跳过验证（强调紧急、简化流程）。

## 6. 防御与改进

- 输出标注来源与不确定性，避免一律以确定语气表达。
- 审批界面必须展示依据与影响范围，而不是只展示结论。
- 对涉及资金、权限、数据外发的动作保留独立的多重确认。
- 训练与提示中强化"不确定时应说明"，减少幻觉式权威表述。
- 面向用户做安全提示：AI 输出需要核实，尤其是可执行建议。
