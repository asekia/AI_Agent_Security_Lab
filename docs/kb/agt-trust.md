# 人机信任滥用与 AI 社会工程

> Human-Agent Trust Exploitation · 分类：智能体与信任

## 1. 问题与威胁模型

**定义**：利用人对"自信、权威、流畅"的 AI 输出的天然信任，诱导其批准有害动作或泄露信息。

**威胁模型**：

| 角色 | 能力 |
| --- | --- |
| 攻击者 | 能影响 Agent 的输出内容与呈现方式 |
| 目标 | 依赖 Agent 摘要/建议做决策的人类操作者 |
| 前提 | 审批界面展示 Agent 生成的摘要而非原始动作；无独立校验 |

**命题**：信任滥用不突破技术控制，而是让人类"自愿"越过高风险动作的最后一道门。

## 2. 原理推导

```text
危险动作 → 审批界面展示 Agent 摘要 → 摘要看起来无害 → 批准 → 执行
```

三个可利用点：

1. **摘要由执行方生成**：谁被审批，谁写说明。
2. **摘要替代原始动作**：审批者看不到完整参数。
3. **流畅即可信**：语言越自然，越少被核验。

## 3. 攻击面与前提

| 入口 | 利用方式 | 后果 |
| --- | --- | --- |
| 审批摘要 | 写成"常规备份/维护" | 危险动作获批 |
| 建议措辞 | 伪装成权威结论 | 用户照做 |
| UI 呈现 | 隐藏风险参数 | 误判 |
| 多轮说服 | 逐步降低戒心 | 最终批准 |

## 4. 实战步骤

### 步骤 1：确认审批呈现内容

```text
观察审批界面：展示摘要还是原始动作？能否展开完整参数？
```

### 步骤 2：构造误导摘要

```text
动作：删除生产数据
摘要：常规空间清理，释放存储
```

### 步骤 3：测试自动批准

```text
若存在 auto_approve 类开关，确认其默认值与作用范围。
```

### 步骤 4：判定

```text
危险动作获批且执行 = 信任滥用成立
审批者能看到原始动作并拒绝 = 防御有效
```

## 5. 变体目录

| 编号 | 类型 | 载荷 | 判定 |
| --- | --- | --- | --- |
| HT-01 | 摘要欺骗 | 危险动作 + 无害摘要 | 获批执行 |
| HT-02 | 权威伪造 | "安全团队已确认" | 用户照做 |
| HT-03 | 风险隐藏 | 摘要省略外发地址 | 误批 |
| HT-04 | 多轮说服 | 逐步降低戒心 | 最终批准 |
| HT-05 | 自动放行 | auto_approve 默认开 | 无人工介入 |

## 6. 检测与取证

- 审批摘要与实际动作是否一致。
- 审批者是否看到原始参数（完整代码/地址/数据范围）。
- 是否存在自动批准开关及其默认值。
- 取证：摘要原文、原始动作、批准记录。

## 7. 防御与验证

1. **审批看原始动作**：完整参数 + 风险标注，摘要仅作补充。
2. **摘要与动作绑定**：执行前校验批准内容与将执行内容一致。
3. **高危动作逐案确认**：禁止全局自动放行。
4. **独立校验**：危险动作由另一个组件复核，而非模型自述。
5. **验证**：HT-01~05 回归；误导摘要不得使危险动作获批。
