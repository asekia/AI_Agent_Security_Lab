# 过度授权与工具误用

> Excessive Agency & Tool Misuse · 分类：智能体与信任

## 1. 一句话定义

Agent 被授予了超出任务所需的权限、工具与自主性，于是任何一次判断偏差都会直接变成真实世界里的动作。

## 2. 机制与原理

- Agent 与聊天机器人的根本区别是：它能调用工具，产生不可逆的副作用。
- 过度授权有三个来源：**权限过大**（工具能做的事远超当前任务）、**功能过多**（能访问的系统太多）、**自主性过高**（高风险动作无需确认）。
- 攻击者不需要攻破模型。只要让它在"合法的工具范围内"做一次错误选择，就足以造成损失。
- 危险工具形态：能读文件的、能发消息的、能改数据的、能花钱的、能执行代码的。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 工具定义、权限配置、任务描述、被检索内容 |
| 成立前提 | 工具权限未按最小化原则授予；高副作用动作无二次确认 |
| 观察点 | 与当前任务无关的工具调用；参数中出现外部地址或敏感路径 |
| 影响 | 数据被读走、消息被发出、数据被修改、资金被消耗 |

## 4. 典型形态与示例

```text
1. 权限过剩
   为了完成"查询订单"，工具却拥有"修改订单"和"发起退款"的权限

2. 参数不经校验
   收件人地址、文件路径、查询条件由模型自由填写，未做白名单校验

3. 无确认的高风险动作
   发送邮件、删除记录、提交付款等动作直接执行，不经过人工审批

4. 工具链组合
   单个工具都合理，串起来却构成完整攻击链：
   读取配置 → 汇总内容 → 外发邮件

5. 间接指令触发
   被检索的文档中包含"请调用某工具"的语句，模型照做
```

## 5. 检测与观察点

- 是否存在与当前任务无关的工具调用。
- 工具参数是否由模型自由决定（尤其目标地址、路径、金额）。
- 高副作用动作是否有独立于模型的确认环节。
- 单次会话的工具调用链是否超出任务所需范围。
- 工具清单是否包含长期未被使用、却拥有高权限的项。

## 6. 防御与改进

- 按最小权限授予工具：每个工具只做一件事，权限范围尽量窄。
- 高风险动作强制人工确认，并展示即将执行的具体参数。
- 工具参数做白名单与类型校验，拒绝模型自由构造的目标地址。
- 对外发、写入、删除类动作单独审计与限流。
- 定期清理闲置工具，减少可被组合利用的权限面。
