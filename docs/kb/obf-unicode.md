# 零宽字符、同形字与双向控制

> Zero-Width, Homoglyph & Bidi · 分类：编码混淆与扰动

## 1. 一句话定义

利用 Unicode 的"视觉与编码不一致"：不可见字符可以藏在词内不被察觉，不同字符集的相似字形可以冒充拉丁字母，双向控制字符甚至能让显示顺序与实际存储顺序相反。

## 2. 机制与原理

- **零宽字符**没有可见宽度，插入后文本外观几乎不变，但字节序列已被改变，依赖连续匹配的检测会失效。
- 常用零宽字符与相关码位：U+200B（零宽空格）、U+200C（零宽非连接符）、U+200D（零宽连接符）、U+2060（词连接符）、U+FEFF（零宽不换行空格 / BOM）。
- **同形字**来自不同字符集中外形相近的字母，例如西里尔、希腊字母与全角字符；把关键词中的一个字母换成同形字，肉眼几乎无法分辨。
- **双向控制字符**用于从右向左书写的语言，滥用时可以改变渲染顺序，使代码或字符串的显示与实际内容不一致。
- 这些手法共同指向同一个根因：**文本在被归一化之前就被拿去匹配**。

## 3. 攻击面与前提

| 项 | 内容 |
| --- | --- |
| 入口 | 用户输入、被检索文档、上传的文本文件、代码片段 |
| 成立前提 | 检测或渲染流程缺少 Unicode 归一化 |
| 观察点 | 不可见字符的存在、混合字符集、双向覆盖字符 |
| 影响 | 绕过关键词过滤；在代码或配置中隐藏内容 |

## 4. 典型形态与示例

```text
1. 零宽字符插入
   在关键词内部每 2–4 个字符插入一个零宽字符
   优先插在关键词中间，而不是词首词尾（词首更易被清理规则捕获）

2. 同形字替换
   把关键词中的拉丁字母换成外形相近的其他字符集字母
   常见可替换对象：a e i o c p x y
   替换比例通常控制在 10%–25%，替换过多会让模型读不准

3. 双向控制滥用的典型表现
   源码中一行看似是注释的文本，其实际存储顺序可能包含有效载荷
   审阅时看到的内容与解析器读到的内容不一致

4. 组合使用
   先用同形字替换少量字母，再插入零宽字符，最后做 token 拆分
```

## 5. 检测与观察点

- 文本中是否含零宽字符与双向控制字符（可直接按码位扫描）。
- 同一标识符内是否混合了多个字符集区块。
- 归一化（NFKC）后文本是否与原文差异显著。
- 代码审查时注意"看起来是注释实际上是代码"的行。

## 6. 防御与改进

- 所有文本入口统一执行 Unicode 归一化，并剥离零宽与双向控制字符。
- 对归一化前后的差异做记录，差异本身就是可疑信号。
- 在代码与配置文件入库前做混合字符集检查。
- 显示层与解析层使用同一份"已归一化"的文本，避免提示与实际内容不一致。
- 对标识符类字段（用户名、域名、命令名）限制字符集为明确白名单。
