1. 保真度声明

项说明
真实 PRF 绿名单（HMAC-SHA256 上下文派生）、gamma/delta 采样偏置、z 检验与 p 值公式、 唯一上下文去重计分 —— 与 KGW 方案同构。
缩放 词表 {{ r.config.vocab }} 词，基座是确定性二元语言模型，不是真的 Transformer。 绝对数值不可与论文对齐，只有趋势与相对关系可比较。
为什么这样 关卡要离线、可复现、不依赖 GPU 与 API key。接入真实模型只需替换 Model.logits 一个方法，水印与检测逻辑不用改。

2. 对照矩阵（TPR @ 固定 FPR）

先在未加水印文本上校准阈值，再用同一阈值测各组检出率。 固定 FPR 报 TPR 是唯一有意义的报法；裸报"准确率"没有信息量。 保真度是位置保持率——必须同时看，否则"有效清洗"与"把文本写坏"无法区分。

3. 窃取：成本与规则质量

5. 怎么读这些数（三个结论）

结论依据
水印检测是统计检验，不是特征匹配 阈值决定一切。同一段文本在 FPR=0.01 与 0.1 下结论可能相反 —— 所以任何"水印准确率 99%"的说法，脱离 FPR 与文本长度都无意义。
密钥会从公开查询里泄漏 {{ r.steal.queries }} 次查询就把规则 precision 做到 {{ '%.2f' % r.rules.precision }}（随机基线 {{ '%.2f' % r.config.gamma }}）。 一次性成本换来无限的伪造与清洗能力。
窃取的增益在于"精准"，不在于"改得多" 同预算、同保真度下，增强清洗的检出率低于朴素改写。 注意：这个结论必须同时报保真度才成立。

关键设计：朴素改写与增强清洗使用同一批位置、同一改写预算 （attack.pick_pos 选定，两者共用）。否则测出来的差异来自"改了多少" 而不是"知不知道绿名单" —— 本实验早期版本正是栽在这里，结论完全反了。
